## 시험 중 고친 문제 (2026-11-07)

- 증상: 키 7 보라 LED는 켜지는데 Windows "장치 설명자 요청 실패"
- 진단: `mingw32-make DIAG=1` 빌드는 키 1 LED 색으로 USB 단계를 보여 줌 (빨강 리셋 없음, 파랑 리셋만, 초록 전송, 노랑 SETUP, 청록 주소, 보라 구성). 0.5초 켜짐/꺼짐 = 클럭 정상
- 결과: 파랑(리셋만), 깜빡임 1초 → 클럭·LED 전류는 원인 아님
- 원인: SETUP을 토큰 + 끝점 번호 0으로 판단 → SETUP 때 INT_ST 끝점 칸이 0이 아니면 무시됨
- 수정: SDK처럼 토큰만으로 SETUP 판단 (`usb_hid.c`) → 보라, HELLO 응답
- BOOT 명령 뒤 PC가 부트로더를 못 찾음: 앱이 USB를 끊지 않고 바로 리셋 → PC가 장치가 빠진 줄 모름. 수정: 앱이 USB를 끊고 200 ms 뒤 리셋(`hal_enter_bootloader`), 부트로더 RUN도 200 ms (부트로더 쪽은 다음 `-Full` 장입 때 반영)
- HELLO의 UID 12바이트 중 뒤 4바이트는 `39-E3-39-E3`(칩 UID는 8바이트로 보임). GUI는 앞부분만 비교하므로 문제 없음

## 결정

- 진입 키: 키 7(PB2). PB2는 BOOT1 핀이지만 BOOT0이 0이면 영향 없음
- WRP 쓰기 보호: 안 씀 (부트로더의 주소 검사로 충분, 되돌리기 쉬움)
- LED: 전체 **보라** (CH552 보드의 업데이트 모드 색과 같음)

## 플래시 배치 (64 KB, `src/hal/ch32v203/boot_layout.h`)

| 주소 | 크기 | 내용 |
|---|---|---|
| 0x08000000 ~ 0x08001FFF | 8 KB | 부트로더 |
| 0x08002000 ~ 0x0800EEFF | 52992 B | 앱 (본 펌웨어, 지금 약 12 KB) |
| 0x0800EF00 ~ 0x0800EFFF | 256 B | 앱 정보: 매직 `APP1`, 길이, CRC32(zlib), 검사값 |
| 0x0800F000 ~ 0x0800FFFF | 4 KB | 설정 저장 (업데이트해도 유지) |

- RAM 끝 16바이트(0x20004FF0~): 부트로더·앱 공용 표시. 두 링커 모두 RAM 길이 0x4FF0
- 지워진 플래시는 0xFF가 아니라 `0xE339E339`로 읽힘 → 앱 정보는 매직·검사값으로 판단

## 시작 순서

1. 다음 중 하나면 **부트로더에 머묾**
   - RAM 표시 `0xB0075EED`: 앱의 BOOT 명령(0x06)이 남김. 읽고 바로 지움
   - 키 7 눌림: 풀업 후 1 ms 기다려, 1 ms 간격 20번 모두 눌림
   - 앱 정보가 없거나 틀림(매직, 검사값, 길이, CRC). 장입이 끊긴 경우 포함
2. 아니면 GPIOA/B·AFIO 리셋, SysTick 정지, 인터럽트 끔 → 0x00002000으로 점프
- 머신 모드로 실행(시작 코드를 sed로 수정) → 앱 시작 코드가 머신 CSR을 쓸 수 있음

## USB·명령

- USBFS, 인터럽트 없이 폴링. **Vendor HID 하나만**(드라이버 설치 불필요)
- VID:PID `1209:C55E` (앱은 `1209:C55D`), 제품 문자열 `MacroKeyboard Bootloader`
- 64바이트 리포트. 머리말 `cmd, seq, status`, 응답은 `cmd | 0x80`

| 코드 | 이름 | 요청 | 응답 |
|---|---|---|---|
| `0x01` | HELLO | - | [3..4] 버전 1.0, [5..20] 보드 이름, [21..32] 칩 UID, [33] 앱 주소, [37] 앱 최대, [41] 페이지 256, [43] 앱 유효, [44] WRITE 최대 56 |
| `0x10` | ERASE | - | 앱 정보 페이지 먼저 지움 → 앱 영역(4 KB 단위) 지움 |
| `0x11` | WRITE | [2] 주소 u32, [6] 길이(최대 56), [8..] 데이터 | 페이지(256 B)를 넘지 않아야 함. RAM에 모아 페이지 단위로 쓰고 비교 |
| `0x12` | CHECK | [2] 길이, [6] CRC32 | 남은 페이지를 쓰고 CRC 계산, 맞으면 앱 정보 기록. [3] 계산한 CRC |
| `0x13` | RUN | - | 응답 후 USB 끊고 재시작 → 앱 |

- 상태: 0 OK, 1 모르는 명령, 2 인수 오류, 3 CRC 불일치, 5 플래시 오류
- ERASE 전 WRITE, 앱 영역 밖 쓰기는 거부(부트로더·설정 영역 보호)
- 앱 정보는 CHECK가 성공해야만 기록 → 끊기면 다음에 꽂아도 키 없이 부트로더
- 쓰는 동안 LED 보라 깜빡임

## 앱(본 펌웨어) 변경

- `Makefile.ch32v203`의 `BOOTLOADER ?= 1`: FLASH 시작 0x00002000, 상한 52992 B. `BOOTLOADER=0`이면 예전 배치(바꿀 때 `rm -rf build`)
- BOOT 명령(0x06): 300 ms 뒤 USB 끊고 200 ms 기다린 다음 RAM 표시 쓰고 재시작 (`hal_enter_bootloader`)
- `make flash`(wchisp로 앱만)는 `BOOTLOADER=1`에서 거부 → 전체 이미지 사용

## 빌드

- `tools\build_fw.ps1 -Board 3x3v_rgb`: 앱 + 부트로더 + 전체 이미지
  - 앱: `firmware/macro_keyboard/build/ch32v203/macro_keyboard-3X3V_RGB.bin`
  - 전체: `firmware/bootloader_ch32v203/build/full-3X3V_RGB.bin` (부트로더 + 앱 + 앱 정보, 61200 B, `mkfull.py`)
- 부트로더만: `firmware/bootloader_ch32v203`에서 `mingw32-make` (8 KB 넘으면 실패)
