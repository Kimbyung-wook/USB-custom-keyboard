## 진단 도구

| 도구 | 용도 |
|---|---|
| `tools/usb_monitor.ps1 -Seconds 180` | 지정 시간 동안 새로 붙거나 떨어지는 USB/HID 장치 기록. 꽂았을 때 Windows가 **무엇이라도** 감지하는지 확인 |
| `tools/usb_monitor.ps1 -History` | 부트로더(`4348:55E0`)와 펌웨어(`1209:C55D`) 장치의 **마지막 연결/분리 시각**과 드라이버. 몇 초만 나타났던 장치도 확인 가능. CH32V203 보드(8·9키)의 자체 부트로더(`1209:C55E`)는 대상 아님 → `hidboot info` |
| `tools/flash.ps1 -Hex <파일>` | 부트로더가 나타나는 즉시 업로드(5초 제한 대응). 진입 핀도 함께 기록 |
| `tools/flash.ps1 -Board sayo_3x3` | CH32V203 보드를 자체 부트로더로 장입 (8키는 `sayo_2x4`). `-Full`: BOOT 브리지로 wchisp가 부트로더만 쓴 뒤, 진입 키를 누른 채 다시 꽂으면 앱을 HID로 |
| `tools/check_device.py` | 장입 직후 점검: USB, HELLO, 보드·칩 정보, 설정 읽기. `--write`/`--verify`로 저장 유지 확인 (`uv run python`으로 실행). `--board` 생략: 키보드가 HELLO로 알린 보드를 `boards.py`에서 찾아 비교(모르는 보드면 실패). `--board none`: 비교 안 함. 기능은 `boards.py`에 적힌 기능을 모두 가졌는지로 비교 |

- PowerShell 스크립트 실행이 막혀 있으면: `powershell -ExecutionPolicy Bypass -File tools\flash.ps1 -Hex ...`

## 1. 빌드

### 1-1. `sdcc.sh` 94번째 줄 문법 오류 (CH55xDuino 0.0.26, Windows)

**증상**

```
Arduino15/packages/CH55xDuino/tools/MCS51Tools/2026.07.10/wrapper/sdcc.sh: line 94: syntax error: unexpected "(" (expecting "fi")
```

**원인**

- Windows에서는 wrapper 스크립트를 CH55xDuino 내장 **busybox sh**가 실행함
- 0.0.26의 `sdcc.sh`가 bash 전용 배열 문법(`FILTERED_ARGS=()`, `"${FILTERED_ARGS[@]}"`)을 씀
- GitHub 최신 소스(2026-07-10)도 같은 상태

**조치**

1. `%LOCALAPPDATA%\Arduino15\packages\CH55xDuino\tools\MCS51Tools\2026.07.10\wrapper\sdcc.sh`를 `sdcc.sh.orig`로 백업
2. `if [ "$MARK" = "re12" ]; then` 블록의 배열 부분을 아래로 교체

   ```sh
   	# POSIX sh version (busybox sh on Windows has no arrays): rotate through
   	# the positional parameters once, re-appending only the kept arguments.
   	skip_next=0
   	argc=$#
   	while [ $argc -gt 0 ]; do
   		arg=$1
   		shift
   		argc=$((argc - 1))
   		if [ $skip_next -eq 1 ]; then
   			skip_next=0
   			continue
   		fi
   		case "$arg" in
   			-c|-MMD|-MF)
   				skip_next=1
   				continue
   				;;
   		esac
   		set -- "$@" "$arg"
   	done
   ```

3. 아래 `case "$SRC"` 안의 `"${FILTERED_ARGS[@]}"` 세 곳을 모두 `"$@"`로 교체

**참고**

- 같은 파일의 `[[ ... ]]` 문법은 busybox에서도 동작하므로 그대로 둠
- CH55xDuino 재설치·업데이트 시 수정이 사라짐 → 다시 적용
- 확인: test_pinmap 빌드 성공(프로그램 6372바이트, 전역 변수 169바이트)

## 2. 업로드와 부트로더

### 2-1. 부트로더 진입 방법 정리 (CH552 보드)

- CH32V203 보드는 [2-6](#2-6-ch32v203-보드-업데이트-모드와-wchisp), 보드별 요약은 [BOARDS.md](BOARDS.md)

| 상황 | 진입 방법 |
|---|---|
| 제조사 펌웨어가 있을 때 | **키 E를 누른 채 연결** (제조사 펌웨어가 부팅 때 키 E를 보고 점프하는 기능으로 추정) |
| 진입 핀 설정 = P1.5 (현재) | **키 D를 누른 채 연결** (키 D = P1.5, ROM 부트로더가 직접 확인) |
| 진입 핀 설정 = P3.6 | 칩 12번 핀(D+)과 16번 핀(3V3) 사이에 **1.5~2kΩ 풀업**을 연결한 채로 연결 |
| 우리 펌웨어가 있는데 키 D로 장입이 안 됨 | 잠금을 풀고 GUI **[업데이트 모드로 전환]** (BOOT 명령, [MANUAL 8장](MANUAL.md#8-펌웨어-업데이트)) |

- 제조사 펌웨어 시절 WCHISPTool 표시는 `Download Cfg Pin = P1.5`였지만 키 D로 진입 안 됨 → 제조사 펌웨어일 때는 키 E 사용
- 부트로더 버전: WCHISPTool 로그 창 또는 업로더 출력의 `BTVER` / `Bootloader:`에서 확인(첫 장치는 2.5.0)
- ROM 부트로더는 펌웨어를 덮어써도 지워지지 않음
- 키 D로 들어갈 때는 장입 프로그램을 먼저 띄운 뒤 꽂기(부트로더는 수 초 뒤 앱으로 빠져나감). MK6K1NL UID `7de20fbd`는 이 순서로 진입·장입됨(1.7.2 장입, 2026-11-17)
- 그 전 2회 실패(2026-11-17, 타이밍 탓): 1회는 진입 흔적 없음. 2회째는 ROM 부트로더(`4348:55E0`)가 07:57:24에 잠깐 잡혔으나 장입 시작(12초 뒤, vnproch55x "Found no CH55x") 때는 없었음, 그때는 BOOT 명령으로 장입함. 부트로더가 빨리 사라지는 경우는 [2-2](#2-2-부트로더가-약-5초-만에-사라짐)

### 2-3. 다운로드 실패 후 장치가 전혀 인식되지 않음 (복구)

**증상**

- WCHISPTool 자동 다운로드가 `fail`로 끝난 뒤, 그냥 꽂아도 키 E를 누르고 꽂아도 **아무 장치도 안 나타남**(알 수 없는 장치조차 없음)

**진단**

1. `usb_monitor.ps1 -History`: 부트로더가 다운로드 시각(23:17:11~23:17:20, 약 9초)에만 기록되고 이후 없음
2. `usb_monitor.ps1 -Seconds 300` 켜고 그냥 꽂기·키 누른 채 꽂기 각 2회 → 기록 전혀 없음
3. 해석
   - Flash에 펌웨어가 일부만 써져 USB를 못 켜는 상태
   - **실패한 다운로드 과정에서 진입 핀 설정이 P3.6으로 바뀐** 것으로 판단
   - 실패 당시 WCHISPTool 로그가 없어 정확한 실패 원인은 모름

**복구**

1. 가변저항(최대 2kΩ)의 가운데 핀과 바깥 핀 하나 사용, 멀티미터로 **1.5~2kΩ**에 맞춤
   - **0Ω 근처 금지**(D+가 3.3V에 직결됨)
2. USB를 뺀 상태에서 칩 **12번 핀(D+)과 16번 핀(3V3)** 사이에 연결
   - 사이의 13(D-), 14(GND), 15(5V)번 핀에 닿지 않게 주의
3. `tools/flash.ps1 -Hex <파일>` 실행해 두고 USB 꽂음
   - 기본값 `-BootPin P15`가 **진입 핀을 P1.5로 되돌림**
4. 성공 로그 예:

   ```
   Found Device CH552
   Bootloader: 2.5.0
   Write 6372 bytes from bin file.  ... Write complete!!!
   Verify chip                      ... Verify complete!!!
   Reset OK
   ```

5. 저항을 떼고, 다음부터는 키 D로 진입

**예방**

- WCHISPTool 대신 CH55xDuino 업로더(`tools/flash.ps1` 또는 Arduino IDE Upload) 사용
- WCHISPTool을 꼭 써야 하면
  - 자동 다운로드 끔
  - 칩 모델(CH552)과 설정 값 확인 후 수동 다운로드
  - 실패하면 로그 저장

### 2-4. Arduino IDE Upload가 진입 핀을 바꿈

| 구분 | 내용 |
|---|---|
| 증상 | 기본 설정으로 올린 뒤 키 D로 진입 안 됨 → [2-3](#2-3-다운로드-실패-후-장치가-전혀-인식되지-않음-복구)의 풀업 방법 필요 |

### 2-6. CH32V203 보드: 업데이트 모드와 wchisp

**증상**

- GUI 펌웨어 업데이트 창에 칩이 안 나타나거나 [업데이트 모드로 전환]이 꺼져 있음
- `wchisp info`가 장치를 못 찾음

**원인·조치**

- 업데이트 모드는 두 가지
  - **자체 부트로더**(보통): 진입 키(9키: 키 7, 8키: 키 5) 누른 채 꽂기 또는 [업데이트 모드로 전환]. LED 보라, `1209:C55E` HID(드라이버 불필요)
  - **ROM 부트로더**(처음 설치·복구): BOOT 브리지(BOOT1 실크 아래 패드 2개) 이은 채 꽂기. wchisp, `-Full`
- 보라가 안 켜짐: 부트로더가 아직 없음(공장 펌웨어, 예전 펌웨어) → 처음 설치 ([MANUAL 8장](MANUAL.md#처음-설치-공장-펌웨어))
- 보라인데 칩 표에 없음: `uv run python -m gui.core.hidboot info`로 확인. 다른 HID 프로그램 닫기
- 진입 키를 안 눌러도 보라: 앱 정보가 없거나 틀림(장입이 끊김) → 다시 장입
- `wchisp`가 못 찾으면: 브리지 접촉 확인, ROM 부트로더 장치에 WinUSB 드라이버(Zadig) 설치
- 장입 뒤에도 키보드가 동작하지 않으면 브리지를 뗐는지 확인 (붙어 있으면 계속 ROM 부트로더)
- 옛 이름(`3X3V_RGB`, `2X4V_RGB`)을 알리는 키보드(펌웨어 1.7.0, 부트로더 1.0): 같은 보드로 인식되어 `--force` 없이 업데이트됨. `check_device`의 "옛 보드 이름" 안내는 정상
- 새 펌웨어를 올린 뒤 Windows가 새 장치를 설치함: USB 시리얼(보드 이름)이 바뀌어 한 번 그럼. 설정은 남음
- 장입이 시작 전에 거부됨
  - 문구: `<보드>용 펌웨어입니다 (부트로더의 보드: <보드>)` 또는 `펌웨어 식별 정보(MKFW1)가 없습니다 (시험 펌웨어이거나 다른 펌웨어)`, 끝에 `그래도 쓰려면 --force (tools\flash.ps1 -Force)`
  - 원인: `.bin`의 식별 문자열 보드 ≠ 부트로더 HELLO 보드, 또는 식별 문자열 없음. 아무것도 지우지 않았으므로 키보드는 그대로
  - 해결: 그 보드의 파일(`build/ch32v203/macro_keyboard-<보드>.bin`)을 고름. 시험 펌웨어(test_ch32v203) 등 일부러 쓸 때만 `-Force` 또는 GUI [강제 장입]
- ⚠️ 제조사 펌웨어는 읽기 보호: 장입하면 지워지고 되돌릴 수 없음
- `-Full`: wchisp가 앞쪽 8 KB(0x0000~0x1FFF)만 지움 → 우리 펌웨어가 있던 칩은 설정 유지(9키 확인). 공장 펌웨어(읽기 보호)는 전부 지워짐. 자체 부트로더 업데이트도 설정 유지
- 절차: [MANUAL 8장](MANUAL.md#8-펌웨어-업데이트), 부트로더 설계: [BOOTLOADER_CH32V203.md](BOOTLOADER_CH32V203.md). CH573 보드는 [2-7](#2-7-ch573-보드sayo_2b3-부트로더)

### 2-7. CH573 보드(SAYO_2B3): 부트로더

- 설계·절차: [BOOTLOADER_CH573.md](BOOTLOADER_CH573.md)

**업데이트 모드에서 코드 10**

- 증상: 키 4를 누른 채 SW1 켜기 → 장치는 잡히나 "이 장치를 시작할 수 없습니다(코드 10)"
- 원인: 2026-11-13 이전 자체 부트로더가 Windows의 모르는 GET_DESCRIPTOR 요청에 STALL로 답함
- 해결: 고친 부트로더로 다시 설치(ROM 부트로더 + wchisp). 고친 판은 0바이트로 답함 ([BOOTLOADER_CH573.md](BOOTLOADER_CH573.md#windows-코드-10-고친-문제-2026-11-13))

**ROM 부트로더(처음 설치·복구)가 금방 사라짐**

- 진입: USB를 꽂은 채 PB22를 GND에 대고 SW1 켜기 → `4348:55E0`
- 통신이 없으면 약 6~15초 뒤 앱으로 돌아감(관찰. 정확한 시간 확인 필요) → 진입 직후 바로 `wchisp info`·장입
- SW1이 꺼져 있으면 USB를 꽂아도 장치가 안 나타남(칩 전원이 SW1 뒤)

**wchisp가 장치를 못 찾음**

- ROM 부트로더 장치에 WCH 드라이버(`CH375`)가 붙어 있으면 wchisp가 못 엶 → Zadig로 **WinUSB** 드라이버 설치(CH552의 [2-5](#2-5-windows-드라이버)와 다름)
- WCHISPTool은 CH375 드라이버로 동작. 둘을 같이 쓰지 않음

**그 밖**

- 자체 부트로더가 옛 이름 `BT_2X3`을 알림: 같은 보드로 인식(`gui/core/boards.py` 이 보드의 `aliases`). 정상
- 빨강 LED가 깜빡이고 키 입력이 안 됨: 업데이트 모드. 키를 누르지 않고 SW1을 껐다 켬. 그래도 같으면 앱 정보가 없거나 틀림 → 앱을 다시 장입
- ⚠️ 공장 펌웨어는 읽기 보호. 장입하면 동글 짝짓기를 포함해 지워지고 되돌릴 수 없음

### 2-8. 동글(CH582F): 짝짓기·장입

- 동글 펌웨어: [firmware/dongle_ch582/README.md](../firmware/dongle_ch582/README.md), 보드: [BOARD_DONGLE_CH582.md](board/BOARD_DONGLE_CH582.md). 아직 장입·하드웨어 확인 전 → 아래는 설계 기준

- 32 kHz 크리스털이 없는 동글은 연결 안정성 확인 필요(SDK는 central에 크리스털을 권함)

**다시 장입하려면**

- 동글 펌웨어는 앱에서 들어가는 부트로더가 없음 → ROM 부트로더 필요
- 진입(추정): 칩 17번 핀(PB22)을 GND에 댄 채 USB 꽂기. 동글 기판에 패드가 없어 칩 핀에 직접 대야 함
- 드라이버·wchisp는 [2-7](#2-7-ch573-보드sayo_2b3-부트로더)과 같음

### 3-1. 영문 대신 한글이 입력됨

| 구분 | 내용 |
|---|---|
| 증상 | `P1.1` 대신 `ㅖ1.1` 입력됨 |
| 원인 | HID 키보드는 문자가 아니라 **키 위치**를 보냄. `P` = Shift+P인데, Windows 입력기가 한글 모드면 두벌식 Shift+P인 `ㅖ`가 됨. 숫자·기호는 한/영과 무관하게 그대로 나옴 |
| 조치 | 한/영 키로 영문 모드 전환(작업 표시줄 입력기 표시 "A") |
| 남은 과제 | 최종 펌웨어도 같은 문제. 출력 전에 한/영 전환키를 보내는 매크로 같은 대책 검토 |

| 조치 | 본 펌웨어에서 방향을 뒤집음 |

### 3-4. 본 펌웨어에서 LED가 켜지지 않음 (v1.0 첫 빌드)

**증상**

- test_pinmap에서는 LED가 켜졌는데, macro_keyboard v1.0 첫 빌드를 올리면 전혀 안 켜짐

**원인 후보** (셋을 한꺼번에 고쳐서 어느 것이 결정적이었는지는 미확인)

| | test_pinmap (켜짐) | v1.0 첫 빌드 (안 켜짐) |
|---|---|---|
| 데이터를 보내는 LED 수 | 8개분 | 1개분 |
| 보내는 빈도 | 0.5초마다 | 색이 바뀔 때 한 번 |
| 밝기 | 40 | 대기 파랑 12 |

- 가장 유력한 원인: **LED 수**
  - WS2812는 체인 앞에서부터 데이터를 나눠 받음 → 보이는 LED가 체인의 첫 번째가 아니면 1개분 데이터로는 안 켜짐
  - "LED는 하나"라는 관찰은 8개분을 같은 색으로 보낸 상태에서 한 것

**조치 (2026-10-26)**

- `macro_keyboard.ino`의 `showColor` 수정
  - 8개분 모두에 같은 색 전송
  - 0.2초마다 다시 전송
  - 밝기 40으로 올림
- 업로드 후 파랑으로 켜지는 것 확인

### 3-6. 키 C를 누르면 `CCW`/`CW`가 입력됨 (MK6K1NL, v1.5.0 이전 빌드)

**증상**

- 노브 바로 옆 키 C를 누르면 `C` 대신, 또는 `C`와 함께 노브 회전(`CCW`, 가끔 `CW`) 입력됨
- 키 C의 LED는 정상으로 켜짐

**진단**

- [test_mk6k1nl](../tests/hw/mk6k1nl/test_mk6k1nl/README.md) RAW 모드로 노브 신호 기록
- 노브가 칸 사이에 걸쳐 `AB 10`에서 쉬고 있었음
- 키 C를 누르는 흔들림에 B 접점이 `10 ↔ 11`을 오감
- 이전 펌웨어는 `11`에 닿을 때 방향 값이 0이 아니면 한 칸으로 셈 → 한 단계 흔들림이 회전으로 입력됨
- 노브를 칸에 두거나 손으로 잡고 누르면 신호 변화 없음

**조치**

- 펌웨어 v1.5.0(최종 빌드)부터 한 칸(4단계) 중 **같은 방향으로 2단계 이상** 움직여야 회전으로 셈(`ENC_MIN_STEPS`)
- 두 보드 모두 적용
- 노브 신호: [BOARD_MK6K1NL 노브 신호](board/BOARD_MK6K1NL.md#노브-신호) 참고

### 3-7. MK6K1NL 제조사 펌웨어에서 업데이트 모드로 들어가지 않음

### 3-8. 9키(SAYO_3X3): 1줄 LED가 파랑만 켜짐

### 3-10. 무선(SAYO_2B3): 붙었다 끊기기를 반복

**증상**

- 재페어링(키 5 + 키 6을 2초, 또는 키 5를 누른 채 SW1 켜기) 뒤 PC·폰에 붙었다 끊기기를 반복, 지금 슬롯의 파랑(슬롯 1/2/3 = L8/L7/L6)이 빠르게 깜빡임. 최대 60초 뒤 멈춤(파랑 꺼짐)

**원인**

- 재페어링이 키보드의 그 슬롯 본딩(암호 키 LTK)을 지웠는데 Windows는 옛 `SAYO_2B3` 장치와 옛 LTK를 그대로 가짐 → 다시 붙을 때 옛 LTK로 암호화를 시작 → 키보드에는 그 키가 없어 실패 → Windows는 재페어링하지 않고 끊음 → 반복 (펌웨어 세션 분석, 증상은 1단계 펌웨어에서 기판 확인 2026-11-14)
- 지금 펌웨어는 재페어링한 슬롯이 새 주소라 PC·폰에 새 장치로 보여 잘 안 생김(추정). 남은 옛 항목은 그래도 지우는 것이 좋음

**해결**

- PC·폰에서 옛 `SAYO_2B3` 장치를 **제거**(Windows: 설정 → Bluetooth 및 장치 → `SAYO_2B3` → 장치 제거)
- 그 슬롯에서 키 5 + 키 6을 2초(또는 키 5를 누른 채 SW1 켜기) → "장치 추가"로 다시 연결 ([MANUAL 11장](MANUAL.md#블루투스-슬롯-3개))

**그 밖**

- 파랑이 꺼지고 연결이 안 됨: 60초 광고가 끝남 → 아무 키나 누르면 다시 시도(그 키는 입력 안 됨)
- USB 케이블이 꽂혀 있으면 블루투스는 끊김(유선 우선). 블루투스로 쓰려면 케이블을 뽑음

### 3-11. 무선(SAYO_2B3): 새 펌웨어로 올린 뒤 연결 안 됨

**증상**

- 펌웨어를 올린 뒤 예전에 페어링한 PC·폰이 붙지 않음. 지금 슬롯의 파랑이 빠르게 깜빡임(페어링 대기)

**원인**

- 2026-11-16 판(131,648 B)부터 블루투스 짝 정보(SNV) 위치가 Data-Flash 0x7E00 → 0x7C00으로 옮겨짐(본딩 4개 저장) → 예전 짝 정보를 못 읽음
- 1단계 펌웨어에서 슬롯 3개 펌웨어로 올릴 때도 키보드 주소가 바뀌어 같은 증상

**해결**

- PC·폰에서 옛 `SAYO_2B3` 장치를 제거하고, 슬롯마다 "장치 추가"로 다시 페어링 ([MANUAL 11장](MANUAL.md#블루투스-슬롯-3개))
- 문자열·패턴 암호 설정은 그대로(설정은 0~2 KB, 짝 정보와 따로)

### 3-12. 무선(SAYO_2B3): 페어링은 되나 키 입력이 안 됨

**증상**

- 블루투스로 페어링·연결은 되고 배터리 %도 보이는데, 키를 눌러도 PC·폰에 입력이 안 됨. USB 케이블로는 입력됨

**원인**

- 2026-11-16 이전 판(131,076 B 등)의 문제. 슬롯 주소 종류 불일치(static 바이트를 public으로 광고), 재연결 때 암호화 미시작, 본딩 1개만 저장 등 ([SAYO_2B3 6절 이력](board/BOARD_SAYO_2X3B_RGB.md#6-본-펌웨어에서의-동작))

**해결**

- 펌웨어를 2026-11-16 판(131,648 B, CRC32 3ACC4E29) 이후로 업데이트 → [3-11](#3-11-무선sayo_2b3-새-펌웨어로-올린-뒤-연결-안-됨)처럼 다시 페어링
