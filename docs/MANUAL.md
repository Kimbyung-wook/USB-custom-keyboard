## 1. 한눈에 보기

- 그림·예시는 6키 MK6K1N 기준. 다른 보드 배치는 [BOARDS.md](BOARDS.md)

```
 ┌───────────────────────────────┐
 │  [A]   [B]   [C]      (노브)  │   노브: 돌리기(시계/반시계) + 누르기
 │  [D]   [E]   [F]       LED    │
 └───────────────[USB]───────────┘
```

- **슬롯 9개**: 키 A~F + 노브 세 동작(시계 방향 한 칸, 반시계 방향 한 칸, 누르기)에 문자열 하나씩
- 키를 누르면 저장된 문자열이 **키보드로 타이핑한 것처럼** 입력됨
  - 글자(`Hello{ENTER}`), 단축키(`{CTRL+C}`), 대기(`{DELAY:500}`) 모두 가능
- 문자열은 PC의 **설정 프로그램(GUI)**으로 넣고 고침
  - 키보드에 저장되므로 GUI가 없는 PC에서도 그대로 동작함
- **패턴 암호**를 정하면 꽂을 때마다 잠김. 키와 노브로 암호를 입력해야 사용 가능

### LED 색 요약

| LED | 뜻 |
|---|---|
| 꽂자마자 약 6초 동안 색이 천천히 바뀜 → 잠깐 꺼짐 | **LED 점검** (모든 보드). **키마다 LED인 보드**(MK6K1NL, SAYO_3X3, SAYO_2X4, SAYO_2X6)는 빛 하나(SAYO_2X6은 마주 보는 빛 2개)가 키 둘레를 1번 키(MK6K1NL은 A)부터 시계방향으로 흐름(이웃한 두 칸이 번갈아 밝아지고 어두워짐, 1초에 한 바퀴, SAYO_3X3 가운데 5번은 계속 켜짐). **MK6K1N**은 LED 1개의 색만 바뀜. 그동안 키 입력은 되지만 키 LED 표시는 없음. 안 켜지는 색이나 키가 있으면 LED 이상 |
| 꺼짐 + 3초마다 빨강 짧게 깜빡 | **잠김**. 키를 눌러도 반응 없음 |
| 빨강 계속 켜짐 | **패턴 암호 입력 중**(풀기 또는 다시 잠그기). **MK6K1NL**은 누른 키의 LED가 잠깐 꺼짐(노브는 전체가 잠깐 꺼짐) |
| 빨강 계속 깜빡 (약 0.5초 간격) | **차단**. 암호 5번 틀림. 다시 꽂아야 함 |
| 파랑 | **사용 가능**(잠금 풀림 또는 패턴 암호 안 씀) |
| 초록 | **키를 누르는 동안**. 떼면 바로 파랑(짧게 눌러도 최소 0.2초, 노브 회전은 0.2초). 긴 문자열은 뗀 뒤에도 파랑인 채 계속 입력됨. **키마다 LED인 보드**(MK6K1NL, SAYO_3X3, SAYO_2X4, SAYO_2X6)는 누른 키의 LED만 초록, 나머지는 꺼짐(검은 키캡에서 잘 보이게). 노브를 누르는 동안·돌릴 때는 모두 초록 |
| 흰색 (0.3초) | GUI에서 설정 저장함 |
| 보라 | 펌웨어 업데이트 모드로 들어가는 중 |

- 키마다 LED인 보드: 초록과 꽂을 때 LED 점검 외의 모든 표시는 모든 LED가 같은 색

## 2. 처음 사용하기

1. 키보드를 PC의 USB 포트에 꽂음. **이때 아무 키도 누르지 않음**
   - 진입 키(6키: 키 D, 9키: 키 7, 8키: 키 5)를 누른 채 꽂으면 펌웨어 업데이트 모드로 들어감([8장](#8-펌웨어-업데이트))
2. Windows가 자동으로 인식함. 드라이버 설치 필요 없음
3. 설정 프로그램 실행([5장](#5-설정-프로그램gui-사용-방법)). 상단에 `● 연결됨`이 보이면 준비 완료
4. 키를 고르고 문자열 입력 → **[장치에 저장]**. LED가 흰색으로 잠깐 빛나면 저장됨
5. 메모장을 열고 키를 눌러 입력되는지 확인

> **한/영 전환 주의**
> - 키보드는 영문 자판 기준으로 키를 보냄
> - Windows가 **한글 입력 상태**이면 `Hello`가 `ㅗ디ㅣㅐ`처럼 나옴
> - 입력받을 창을 **영문 입력 상태**로 두고 사용

## 3. 키보드 사용 방법

### 키 A~F

- 누르면 저장된 문자열이 바로 입력됨
- 입력 중에 다른 키를 눌러도 됨. 최대 8개까지 대기했다가 순서대로 입력함
- 빈 키: 아무것도 입력되지 않음(누르는 동안 LED만 초록)

### 노브

| 동작 | 입력되는 것 |
|---|---|
| 시계 방향으로 한 칸 | "노브 시계 방향" 문자열 (예: `{RIGHT}`, `{DOWN}`) |
| 반시계 방향으로 한 칸 | "노브 반시계 방향" 문자열 (예: `{LEFT}`, `{UP}`) |
| 짧게 누르기 | "노브 누르기" 문자열 (예: `{ENTER}`) |
| **2초 누르고 있기** | 패턴 암호 입력 시작([4장](#4-패턴-암호-잠금)). 패턴 암호를 쓸 때만 |

- 한 칸(딸깍) 돌릴 때마다 한 번씩 입력됨
- 패턴 암호를 쓰면 노브 누르기 문자열은 **뗄 때** 입력됨
  - 이유: 2초 넘게 누르면 문자열 대신 패턴 암호 입력이 시작되기 때문

### Caps Lock

- Caps Lock 상태와 관계없이 저장한 대소문자 그대로 입력됨(`Hello` → 항상 `Hello`)

## 4. 패턴 암호 (잠금)

- 목적: 주변 사람이 키를 눌러 저장된 문자열을 쓰지 못하게 잠금
- 암호: 키와 노브를 정해진 순서로 입력하는 것
- 블루투스(SAYO_2B3)도 같음: 잠긴 동안 입력 안 됨, 패턴으로만 풀림, USB 케이블을 꽂거나 뽑아 유선↔무선이 바뀌어도 잠금 상태 그대로([REQ-LOCK-10](REQUIREMENTS.md#lock-잠금패턴-암호), 펌웨어 확인 중)

### 패턴 암호 정하기

1. GUI의 **패턴 암호** 칸에서 키/노브 버튼을 순서대로 누름
   - 버튼: `A`~`F`(키), `↻`(노브 시계 방향 한 칸), `↺`(노브 반시계 방향 한 칸), `●`(노브 누르기)
   - **2~8단계**. 예: `A → B → C → ↻`
   - 짧을수록 맞히기 쉬우므로 4단계 이상 권장
   - 잘못 눌렀으면 **[⌫ 한 칸 지우기]**, 처음부터는 **[모두 지우기]**
2. **[장치에 저장]** 누름
3. 저장 직후에는 잠기지 않음. **다음에 꽂을 때부터** 잠김

![패턴 암호 칸](images/gui_lock.png)

- 저장 공간 사용: `2 + 단계 수`바이트(4단계면 6바이트). 그만큼 문자열을 적게 넣을 수 있음

### 잠금 풀기

1. 꽂으면 **잠김** 상태(LED 꺼짐, 3초마다 빨강 짧게 깜빡). 키를 눌러도 반응 없음
2. **노브를 2초 누르고 있다가** LED가 **빨강으로 계속 켜지면** 놓음
   - 노브 없는 보드(8/9키): **아무 키나** 2초. 그 키는 입력되지 않음
3. 패턴 암호를 순서대로 입력. 입력 중에는 아무것도 타이핑되지 않음
4. 맞으면 LED **파랑** → 평소처럼 사용

- **틀리면**: 다시 잠김. 노브 2초부터 다시 시작
- 빨강 켜진 채 **10초 동안 입력 없음**: 취소되고 잠김으로 돌아감. 틀린 횟수에 안 들어감
- **5번 틀리면 차단**: 빨강 계속 깜빡, 아무 입력도 안 받음. USB를 뺐다 다시 꽂으면 재시도 가능
- 노브 2초 누르기는 **꽂은 다음에** 함 (노브 없는 보드는 진입 키가 패턴 키와 겹쳐, 꽂으면서 누르면 업데이트 모드로 들어감)

### 다시 잠그기

- 자리를 비울 때 뽑지 않고 잠그는 방법

1. 풀린 상태(파랑)에서 **노브를 2초 누르고 있음**(노브 없는 보드는 아무 키) → LED 빨강 계속 켜짐
   - 노브 없는 보드: 키는 누를 때 입력되므로, 2초 누른 키가 한 번 입력된 뒤 패턴 입력이 시작됨
2. 같은 패턴 암호 입력 → 잠김(꺼짐 + 가끔 빨강 깜빡)

- 틀리면 잠기지 않고 파랑으로 돌아감
- 다시 잠그기를 **5번 틀리면** 그냥 잠김
  - 차단이 아니라 잠김이므로 노브 2초 + 맞는 암호로 바로 풀 수 있음
- 10초 동안 입력 없으면 취소, 파랑으로 돌아감
- 뺐다가 다시 꽂아도 잠김

### 자동 잠금

- 풀린 뒤 한동안 안 쓰면 저절로 잠김

1. GUI 패턴 암호 칸 아래 **자동 잠금**에 분(1~255) 입력. **0분 = 자동 잠금 안 함**
2. **[장치에 저장]** 누름

- 잠기는 조건: 그 시간 동안 **키/노브 입력 없음** + GUI 읽기·저장·테스트 입력도 없음
  - GUI를 켜 두기만 하는 것은 입력으로 치지 않음
- 잠기면 GUI 화면의 설정도 지워짐(저장 안 한 편집 포함). 오래 편집할 때는 중간에 저장
- 패턴 암호가 있을 때만 사용 가능. 패턴 암호를 지우면 자동 잠금도 0분이 됨
- 저장 공간 3바이트 사용

### 잠금 끄기

1. GUI 패턴 암호 칸에서 **[모두 지우기]**
2. **[장치에 저장]**

- 이후에는 꽂자마자 파랑으로 켜짐

### 패턴 암호를 잊었을 때

- 방법: **잠긴 상태 그대로** GUI에서 새 설정을 저장. 또는 [공장 초기화](#공장-초기화)로 모두 지움

1. 키보드를 꽂고 GUI 실행. 상단에 `🔒 잠김` 표시
2. 새로 쓸 문자열 입력. 패턴 암호 칸은 비우거나 새 암호 입력
3. **[장치에 저장]** → "기존 문자열과 패턴 암호를 모두 지웁니다" 경고 → 확인하면 저장됨

- **기존 문자열은 되찾을 수 없음**. 잠긴 키보드의 내용을 못 읽게 하는 것이 이 기능의 목적
- 펌웨어를 다시 올려도 문자열과 패턴 암호는 지워지지 않음. 잊었을 때는 위 방법 사용
- 평소 [JSON 내보내기](#백업-json-내보내기--불러오기)로 백업해 두면 다시 넣기 쉬움

### 보안 수준

- 막는 것: 주변 사람이 키를 눌러 보거나 GUI로 내용을 읽어 가는 것
- 못 막는 것: 키보드를 가져가 펌웨어를 새로 굽는 등 작정한 공격
- **비밀번호처럼 민감한 문자열은 넣지 않는 것**을 권장

## 5. 설정 프로그램(GUI) 사용 방법

### 실행

- 배포된 **`MacroKeyboardConfig.exe`** 실행. Python 설치 필요 없음
- 저장소에서 바로 실행: `uv run python -m gui` (설치 방법은 [gui/README.md](../gui/README.md))
- 키보드가 꽂혀 있으면 자동 연결. 실행 후에 꽂아도 2초 안에 연결됨

### 화면 구성

- 위에서부터 차례로:

| 영역 | 하는 일 |
|---|---|
| **연결 막대** (맨 위 세 줄) | 연결·잠금 상태, 보드와 저장 용량, 펌웨어 버전. 오른쪽에 [연결 끊기] [새로고침] [펌웨어 업데이트] |
| **키 / 노브 선택** | 키보드 모양 그대로의 버튼. 누르면 그 슬롯 편집. 버튼마다 글자 수와 문자열 앞부분 표시 |
| **패턴 암호** | 패턴 암호·자동 잠금 시간 설정, 잠금 사용법 표시([4장](#4-패턴-암호-잠금)) |
| **편집기** | 고른 슬롯의 문자열 편집. 위쪽 버튼으로 특수 키 삽입, 아래에 문법 검사 결과와 문법 요약 |
| **저장 용량** | 전체 글자 수, 더 넣을 수 있는 글자 수, 사용 바이트 |
| **아래 버튼** | [장치에서 읽기] [장치에 저장] [테스트 입력] [공장 초기화] [JSON 내보내기] [JSON 불러오기]. 맨 아래 오른쪽은 프로그램 버전 |

- **[세로 보기]**: 돌려 쓸 수 있는 보드(지금은 준비 중인 JUZH_3B4)만 보임. 보드를 반시계 방향 90°로 돌려 쓸 때의 그림으로 바꿈(키 4행 × 3열이 아래, 노브는 위쪽 왼쪽·오른쪽)
  - 그림만 바뀜. 키·노브 번호, 설정, 노브 회전 방향 표시는 그대로
  - 보드마다 고른 보기를 기억함

### 연결 막대

![연결 막대: 풀린 상태](images/gui_connected.png)

![연결 막대: 잠긴 상태](images/gui_locked.png)

| 표시 | 뜻 |
|---|---|
| `○ 연결 안 됨` | 키보드 없음. 꽂으면 자동 연결. [연결]을 눌러도 됨 |
| `● 연결됨 - 잠금 풀림` / `● 연결됨 - 잠금 안 씀` | 사용 가능. 패턴 암호가 있으면 "잠금 풀림", 없으면 "잠금 안 씀" |
| `🔒 잠김 - 키보드에서 노브를 2초 누른 뒤 패턴 암호를 입력하세요` (노브 없는 보드는 `아무 키를`) | 키보드 잠김. 키보드에서 풀면 2초 안에 자동으로 설정을 읽어 옴 |
| `🔒 잠김 - 5번 틀려서 입력을 막았습니다. 키보드를 다시 꽂으세요` | 차단 상태. 키보드를 다시 꽂음 |

- 연결되면 아래 두 줄에 표시:
  - **보드와 저장 용량**: `MK6K1N (키 6 + 노브 1) / 용량 128바이트`
  - **펌웨어 버전과 빌드 날짜**: `펌웨어 v1.4.0 (빌드 2026-10-27 09:00)`
- 보드 정보를 안 보내는 옛 펌웨어: 보드 뒤에 `· 보드 정보 없음` 붙음
- **[새로고침]**: 키보드 상태를 바로 다시 확인

### 연결되지 않았을 때는 아무것도 보이지 않습니다

- 보안상, 문자열과 패턴 암호는 **연결 + 잠금 풀림** 상태에서 키보드에서 읽어 온 것만 화면에 보임
- 키보드를 뽑거나 키보드에서 다시 잠그면 화면 내용이 **지워짐**(저장 안 한 편집 포함). 고친 내용은 먼저 저장
- 연결 안 된 동안: 편집기, 패턴 암호, JSON 버튼 꺼짐
- 다시 연결되어 풀리면 자동으로 다시 읽어 옴

### 문자열 편집하기

1. **장치 그림**에서 고칠 키나 노브 동작 누름(버튼에 글자 수와 미리보기 표시)
2. 아래 **편집기**에 문자열 입력. 문법은 [6장](#6-문자열-쓰는-법-매크로-문법) 참고
   - 편집기 위 버튼(`{ENTER}`, `{TAB}`, `{DELAY:100}` 등)과 **[조합키 ▾]**, **[특수 키 ▾]** 메뉴로 자주 쓰는 표기 삽입
   - 입력 즉시 문법 검사. 잘못된 곳은 빨간 밑줄, 아래에 몇 행 몇 열이 왜 틀렸는지 표시
3. 표시 확인
   - 저장 안 한 슬롯: 버튼에 `*`
   - 문법 틀린 슬롯: 빨간 글씨
   - 창 제목에도 `*` 붙음

### 저장 용량

- 전체 **128바이트**. 9개 슬롯 합계 최대 **102자**, 패턴 암호를 쓰면 그만큼 줄어듦
- 아래 막대에 `N자 입력 · M자 더 입력 가능` 표시
- 키마다 길이는 자유롭게 나눠 씀(예: 한 키에 40자, 다른 키에 5자)
- `{ENTER}` 같은 표기도 **쓴 글자 수만큼** 차지함(`{ENTER}` = 7자)
- 용량 초과: 막대가 빨간색, **[장치에 저장]** 꺼짐 → 문자열을 줄임

### 장치에 저장

- **[장치에 저장]**: 9개 슬롯과 패턴 암호를 한꺼번에 저장
- 저장 전 검사: 문법, 용량, 패턴 암호(2~8단계, 옛 펌웨어는 4~8단계). 문제가 있으면 알려 주고 저장 안 함
- 확인창에서 [예] → 저장, 키보드 LED 흰색으로 잠깐 빛남
- 키보드가 문자열 입력 중이면 잠시 기다렸다가 저장함
- CH32V203 보드: 저장 도중 전원이 끊기면 다음에 꽂을 때 CRC 불일치 → **빈 설정**으로 시작 (엉뚱한 입력은 없음, 이중 저장은 없음). 저장 중(흰색 LED)에는 뽑지 말고, 미리 [백업](#백업-json-내보내기--불러오기)

### 장치에서 읽기

- **[장치에서 읽기]**: 키보드에 저장된 내용을 다시 불러옴
- 화면에서 고치던 내용이 지워지므로 먼저 확인을 물음
- 저장된 설정이 없으면(새 키보드 등) 빈 슬롯으로 시작

### 테스트 입력

- 키를 누르지 않고 선택한 슬롯이 제대로 입력되는지 시험

1. 시험할 슬롯을 고르고 **[테스트 입력]** 누름
2. 확인하면 **3초 카운트다운** 시작. 그동안 입력받을 창(예: 메모장) 클릭
3. 키보드가 그 슬롯의 문자열을 입력함

- 키보드에 **저장된** 내용이 입력됨. 고친 내용을 시험하려면 먼저 저장

### 백업 (JSON 내보내기 / 불러오기)

- **[JSON 내보내기]**: 9개 슬롯의 문자열을 `.json` 파일로 저장
- **[JSON 불러오기]**: 저장해 둔 파일을 화면에 불러옴. 키보드에 넣으려면 이어서 **[장치에 저장]**
- **패턴 암호는 백업 파일에 들어가지 않음**. 불러와도 화면의 패턴 암호는 그대로
- 키보드가 연결되어 있을 때만 사용 가능

### 공장 초기화

- **[공장 초기화]**: 키보드의 **모든 설정**을 지움: 키·노브 문자열, 패턴 암호, 자동 잠금. 지운 뒤에는 잠금 없는 빈 키보드
  - 블루투스 보드(SAYO_2B3): **모든 슬롯**의 페어링(기억한 기기)도 지우고, 슬롯마다 키보드 주소를 새로 만든 뒤 다시 켜짐(슬롯 1로 돌아감). PC·폰에는 새 장치로 보이므로 남은 `SAYO_2B3` 항목은 제거하고 새로 연결. GUI는 다시 켜진 키보드에 저절로 다시 연결(안 되면 [연결])
  - 페어링 지우기가 없는 옛 펌웨어: 설정만 지우고 "페어링은 남습니다"로 안내
- 풀린 상태: 먼저 고름 → [JSON으로 저장한 뒤 초기화] / [저장하지 않고 초기화] / [취소]. JSON은 키보드에서 읽은 문자열
- **잠긴 상태에서도 됨**: 내용을 읽지 않고 지움("기존 문자열과 패턴 암호는 되찾을 수 없습니다"). 백업은 못 함. 잠겨 있으면 다른 사람이 내용을 볼 수 없게 하려는 것([REQ-LOCK-09](REQUIREMENTS.md#lock-잠금패턴-암호))
- 확인 창이 두 번 나옴. ⚠️ 되돌릴 수 없음
- 상태: 구현됨, 기판 확인 전([REQ-GUI-09](REQUIREMENTS.md#gui))

### 종료

- 저장 안 한 편집이 있으면 종료할 때 확인을 물음

## 6. 문자열 쓰는 법 (매크로 문법)

- 일반 글자는 그대로, `{ }` 안에 쓴 것은 특수 키나 동작으로 입력됨

| 쓰는 법 | 입력되는 것 | 예 |
|---|---|---|
| 영문, 숫자, 기호 | 그대로 | `Hello, World!` |
| 줄바꿈 (편집기에서 Enter) | Enter 키 | |
| `{ENTER}` `{TAB}` `{ESC}` `{BS}` `{DEL}` `{SPACE}` | Enter, Tab, Esc, Backspace, Delete, 스페이스 | `id{TAB}name{ENTER}` |
| `{UP}` `{DOWN}` `{LEFT}` `{RIGHT}` | 방향키 | 노브에 `{UP}` / `{DOWN}` |
| `{HOME}` `{END}` `{PGUP}` `{PGDN}` `{INS}` | Home, End, Page Up, Page Down, Insert | |
| `{F1}` ~ `{F12}` | 기능 키 | `{F5}` (새로고침) |
| `{CTRL+C}` `{ALT+TAB}` `{WIN+R}` | 조합키 | `{CTRL+S}` (저장) |
| `{CTRL+SHIFT+ESC}` | 수식키 여러 개 조합 | 작업 관리자 |
| `{DELAY:500}` | 0.5초 기다리기 (1~10000밀리초) | `{WIN+R}{DELAY:300}notepad{ENTER}` |
| `{{` / `}}` | 글자 `{` / `}` | `{{OK}}` → `{OK}` |

- 수식키: `CTRL`, `SHIFT`, `ALT`, `WIN`. 마지막에 글자 하나나 키 이름
- `+` 글자와 조합: `{CTRL++}`
- 키 이름은 대소문자 구분 안 함(`{enter}`도 됨)
- **한글 등 영문이 아닌 글자는 넣을 수 없음**. 미국(US) 자판 기준으로 입력됨

**예시**

| 하고 싶은 것 | 문자열 |
|---|---|
| 이메일 주소 입력 | `myname@example.com` |
| 인사말 두 줄 (영문만 가능) | `Hello,{ENTER}Thank you.` |
| 메모장 열기 | `{WIN+R}{DELAY:300}notepad{ENTER}` |
| 복사 / 붙여넣기 | `{CTRL+C}` / `{CTRL+V}` |
| 창 전환 | `{ALT+TAB}` |
| 노브로 위/아래 이동 | 시계 방향 `{DOWN}`, 반시계 방향 `{UP}` |

## 7. 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 키를 눌러도 입력 안 됨, LED 꺼짐 (가끔 빨강 깜빡) | 고장 아님, **잠김** 상태. 노브(노브 없는 보드는 아무 키) 2초 누른 뒤 패턴 암호 입력 |
| LED 빨강 계속 깜빡, 반응 없음 | 암호 5번 틀려 **차단**됨. USB 다시 꽂기 |
| 영문 대신 `ㅗ디ㅣㅐ`처럼 한글이 나옴 | 입력받는 창이 한글 입력 상태. 한/영 키로 영문 전환 |
| LED 초록으로 켜진 채 키를 눌러도 입력 안 됨 (KVM 전환, PC 절전 해제 뒤) | 옛 펌웨어의 문제. 다시 꽂으면 풀림. [펌웨어 업데이트](#8-펌웨어-업데이트)하면 안 생김. 지금 펌웨어는 입력 중 전환되면 남은 문자열을 버림(다른 PC에 이어서 입력 안 함) |
| 글자가 일부 빠지거나 순서가 꼬임 | 프로그램이 입력을 늦게 받음. 문자열 중간에 `{DELAY:100}` 추가 |
| 단축키가 안 먹음 (예: `{WIN+R}` 뒤 글자가 사라짐) | 창이 뜨기 전에 글자가 입력됨. `{DELAY:300}`처럼 대기 추가 |
| GUI가 `○ 연결 안 됨`에서 안 바뀜 | USB 다시 꽂기. 다른 설정 프로그램 창이 열려 있으면 닫기 |
| 꽂았는데 키보드로 인식 안 됨 (LED 꺼짐 또는 보라) | 진입 키를 누른 채 꽂아 펌웨어 업데이트 모드로 들어감. 아무것도 누르지 않고 다시 꽂기. CH32V203 보드가 키 없이도 보라면 장입이 끊긴 것 → [8장](#실패했을-때) |
| [장치에 저장]이 꺼져 있음 | 용량 초과(막대 빨간색), 패턴 암호 2단계 미만, 또는 키보드 연결 안 됨 |
| 펌웨어 업데이트에서 "60초 안에 칩을 찾지 못했습니다" | 뽑았다가 진입 키([BOARDS.md](BOARDS.md))를 누른 채 꽂고, 칩이 목록에 나타나면 [장입] 다시 누름. WCHISPTool이 열려 있으면 닫기 |
| GUI에서 "펌웨어 v1.0은 패턴 암호를 지원하지 않습니다" | 펌웨어가 오래됨. [펌웨어 업데이트](#8-펌웨어-업데이트) 또는 패턴 암호 지우기 |
| 자동 잠금 칸이 꺼져 있음 ("펌웨어 1.4.0 이상 필요") | 펌웨어 v1.3 이하. [펌웨어 업데이트](#8-펌웨어-업데이트). 패턴 암호가 없을 때도 꺼짐 |
| 편집하던 내용이 갑자기 지워지고 `🔒 잠김`이 됨 | [자동 잠금](#자동-잠금) 시간 지남. 풀고 다시 읽어 오기. 오래 편집할 때는 중간에 저장 |
| 패턴 암호를 잊음 | [패턴 암호를 잊었을 때](#패턴-암호를-잊었을-때) 참고 |

- 기술적인 문제 해결: [docs/TROUBLESHOOTING.md](TROUBLESHOOTING.md)

### 이력

## 8. 펌웨어 업데이트

- 새 펌웨어 파일을 받았을 때만 필요. 보드마다 파일·진입 키·처음 설치 방법이 다름 → [BOARDS.md](BOARDS.md) "펌웨어 업데이트" 표
  - CH552 보드(MK6K1N, MK6K1NL): `.hex`, WCH ROM 부트로더
  - CH32V203 보드(SAYO_3X3, SAYO_2X4, SAYO_2X6): `.bin`, 자체 HID 부트로더
  - CH573 보드(SAYO_2B3, 준비 중): `.bin`, 자체 HID 부트로더 ([11장](#11-무선-키보드-sayo_2b3와-동글-준비-중))
  - JieLi 보드(JUZH_3B4, 준비 중): 칩 ROM의 USB 다운로드 모드(UBOOT)로 올리는 따로 된 업데이트 창. 진입 → 백업 → 쓰기 → 재시작 순서이고 **지금은 백업까지만**(쓰기는 준비 중). 관리자 권한이 필요하면 창에서 [관리자로 다시 실행]([보드 문서](board/BOARD_KEY12_JUZHEN_V01.md#5-부팅장입))
- 문자열과 패턴 암호는 업데이트해도 그대로 남음 (예외: CH32V203 [처음 설치](#처음-설치-공장-펌웨어))
- 만일에 대비해 올리기 전에 GUI로 [백업](#백업-json-내보내기--불러오기)

### 업데이트 모드 들어가기

| 방법 | 언제 |
|---|---|
| GUI **[업데이트 모드로 전환]** | 키보드가 연결되어 있고 잠금이 풀렸을 때 (키 필요 없음) |
| **진입 키**를 누른 채 꽂기 | 잠겼거나 연결 안 됨. 진입 키는 보드별(MK6K1N·MK6K1NL: 키 D, SAYO_3X3: 키 7, SAYO_2X4: 키 5, SAYO_2X6: 키 7). SAYO_2B3은 키 4를 누른 채 SW1 켜기 |
| 보드별 처음 설치 방법 | 공장 펌웨어, 우리 부트로더가 아직 없음 ([아래](#처음-설치-공장-펌웨어)) |

- 업데이트 모드로 들어갈 때 LED **보라**. 업데이트 모드에서는 키 입력 안 됨
- 실수로 들어갔으면 아무것도 누르지 않고 다시 꽂기

### GUI에서 올리기 (권장)

![펌웨어 업데이트 창](images/gui_firmware.png)

1. 키보드를 꽂고 GUI에서 **잠금 푼 상태**(`● 연결됨`)로 둠
2. 상단 **[펌웨어 업데이트]** 누름
3. 창 맨 위 **장입할 보드** 확인 후 펌웨어 파일 선택
   - 저장소에서 빌드한 그 보드의 파일(예: `macro_keyboard-MK6K1NL.hex`, `macro_keyboard-SAYO_3X3.bin`)이 있으면 미리 골라져 있음. 파일을 골라도 바로 올리지는 않음
   - 장입할 보드: 연결되어 있던 키보드(예: `MK6K1NL · 6키 + 노브 1개, 키마다 LED (CH552G)`)가 골라져 있고, 아래에 업데이트 모드 진입 방법 표시
   - **처음 설치하는 키보드**(공장 펌웨어)나 보드 정보를 안 보내는 키보드: `⚠ 연결된 키보드를 식별할 수 없습니다` 표시 → 장입할 보드를 직접 고름
     - 안내에 그 보드의 처음 설치 방법 표시
     - [장입]을 누르면 고른 보드가 맞는지 한 번 물음
   - 파일 아래에 크기와 **어느 키보드용인지** 표시(예: `✔ 10006 / 14336바이트 (70%) · MK6K1NL용 (CH552) v1.7.0`)
     - 칩 용량보다 크거나 다른 칩용이면 올릴 수 없음
     - 다른 키보드용이거나 식별 정보가 없는 펌웨어
       - CH552 보드: 주황 `⚠` 표시, [장입] 때 한 번 더 물음
       - CH32V203 보드: **빨간** `⚠` 표시. [장입]을 누르면 **"강제 장입"** 확인 상자(기본 단추는 취소). 시험 펌웨어처럼 일부러 쓸 때만 [강제 장입]
4. **[업데이트 모드로 전환]** 누름 → 업데이트 모드, **인식된 칩** 목록에 나타남
   - 칩마다 **파트 번호**(예: `CH552`, `CH32V203`), **시리얼 번호**(칩 고유 ID), 부트로더 버전(예: `2.5.0`, `자체 1.0`) 표시
   - 목록은 1초마다 자동 갱신. [다시 검색]으로 바로 확인 가능
   - 방금 GUI에 연결되어 있던 키보드는 시리얼 번호 옆에 `(방금 연결된 키보드)` 표시
5. 목록에 칩이 하나, `장입할 준비가 되었습니다` 표시되면 **[장입]** 누름
6. 진행 막대가 끝까지 차고 `✔ 장입 완료`가 나오면 **[닫기]** 누름
   - GUI가 다시 연결하고, 연결 막대에 새 펌웨어 버전과 빌드 날짜 표시

**잠겨 있거나 연결 안 된 키보드**

- 4번에서 "키 D(보드에 따라 키 7, 키 5)를 누른 채 다시 꽂으세요" 안내가 나옴
- 뽑았다가 **진입 키를 누른 채** 다시 꽂으면 목록에 칩이 나타남

**[장입]이 눌리지 않는 경우**

- 목록에 칩이 없을 때
- 칩이 **두 개 이상**일 때: 어느 칩에 올릴지 알 수 없음. 장입할 키보드 하나만 남김
- 칩이 고른 보드의 칩이 아닐 때
- 고른 펌웨어가 다른 칩용일 때

### 스크립트로 올리기

- CH552 보드: 업데이트 모드는 몇 초만 유지되므로 스크립트를 먼저 실행
  1. `powershell -ExecutionPolicy Bypass -File tools\flash.ps1 -Hex firmware\macro_keyboard\build\macro_keyboard-MK6K1N.hex`
  2. 키보드를 **키 D를 누른 채** 꽂음
  3. `Verify complete!!!`와 `Reset OK`가 나오면 완료
- CH32V203 보드: 업데이트 모드가 계속 유지됨
  - 진입 키를 누른 채 꽂고 `powershell -ExecutionPolicy Bypass -File tools\flash.ps1 -Board sayo_3x3` (8키는 `sayo_2x4`)
  - 잠금 풀린 키보드는 `-Enter`를 붙이면 키 없이 진입
  - 다른 보드용이나 식별 정보가 없는 `.bin`은 거부됨(지우기 전). 일부러 쓸 때만 `-Force`

### 처음 설치 (공장 펌웨어)

- CH552 보드: 공장 펌웨어의 진입 방법(MK6K1N: 키 E, MK6K1NL: D+ 풀업 저항, [BOARDS.md](BOARDS.md))으로 업데이트 모드 → 위 [GUI에서 올리기](#gui에서-올리기-권장) 3번에서 장입할 보드 고르기
- CH32V203 보드: 자체 부트로더를 한 번 설치 (이후 브리지 불필요)
  1. 키보드 뒷면을 열고 **BOOT 브리지**(BOOT1 실크 아래 패드 2개)를 이은 채 USB 연결
  2. `powershell -ExecutionPolicy Bypass -File tools\flash.ps1 -Board sayo_3x3 -Full` (8키는 `sayo_2x4`)
     - `wchisp info` 결과(칩 CH32V203C8U6, 보드 UID, 보호 없음)를 확인하고 `yes` 입력
     - wchisp가 **자체 부트로더만**(`bootloader-<보드>.bin`, 8 KB 이하) 씀. 지우는 곳은 앞쪽 8 KB(0x0000~0x1FFF, 부트로더 자리)뿐
  3. 안내에 따라 브리지를 떼고 **진입 키**(9키: 키 7, 8키: 키 5)를 누른 채 다시 꽂음 → 보라 LED
  4. 앱을 HID 부트로더로 씀 → 키보드가 새 펌웨어로 시작
     - 우리 펌웨어가 있던 키보드는 **설정이 남음**
     - ⚠️ 공장 펌웨어(읽기 보호)는 보호를 풀 때 **전부 지워짐**(되돌릴 수 없음)
  5. 점검: `uv run python tools\check_device.py`
     - `--board` 생략: 키보드가 HELLO로 알린 보드를 `boards.py`에서 찾아 비교(모르는 보드면 실패). `--board none`: 비교 안 함. 기능은 `boards.py`에 적힌 기능을 모두 가졌는지로 비교
     - 설정 저장 확인: `--write` → USB 다시 연결 → `--verify` → `--restore <백업 파일>`

### 실패했을 때

- 업로드 중에는 키보드를 뽑지 않음
- CH32V203 보드: 펌웨어 1.7.0(옛 보드 이름 `3X3V_RGB`, `2X4V_RGB`)에서 새 펌웨어로 올리면 Windows가 새 장치로 한 번 잡음(USB 시리얼이 바뀜). 설정은 남음. 옛 이름도 같은 보드로 인식되어 업데이트는 그대로 됨
- CH552 보드: 실패하거나 [취소]했으면 키 D를 누른 채 꽂고 다시 시도. ROM 부트로더라 펌웨어와 관계없이 항상 진입 가능
- CH32V203 보드: 장입이 끊기면 다음에 꽂을 때 키 없이도 업데이트 모드(보라) → 다시 장입. 부트로더까지 망가지면 위 처음 설치(`-Full`)
- WCHISPTool 같은 다른 업로드 프로그램은 닫아 둠
- 기술적인 내용: [TROUBLESHOOTING 2장](TROUBLESHOOTING.md#2-업로드와-부트로더), CH32V203 부트로더 설계는 [BOOTLOADER_CH32V203.md](BOOTLOADER_CH32V203.md), CH573(SAYO_2B3)은 [BOOTLOADER_CH573.md](BOOTLOADER_CH573.md)

### 이력

- v1.3: 펌웨어 식별 문자열, `(방금 연결된 키보드)` 표시. v1.2.x 이하 펌웨어는 식별 정보 없음(`⚠`)
- 2026-11-07 (1.7.0): CH32V203 보드 자체 HID 부트로더. CH552 보드의 "노브를 누른 채 꽂기" 진입 없앰. `-Full`은 부트로더만 wchisp로 쓰고 앱은 HID로(우리 펌웨어가 있던 칩은 설정 유지, 전에는 설정도 지움)
- 2026-11-07: 9키 실측 — wchisp는 최소 8섹터(0x0000~0x1FFF) 지움(전에 적은 약 6페이지는 틀림). 부트로더 교체 뒤 키 7로 앱 1.7.0 장입, 설정(슬롯 9개) 유지
- 2026-11-07: CH32V203 보드에 맞지 않는 펌웨어는 빨간 경고 + "강제 장입" 확인, 스크립트는 `-Force`로만
- 2026-11-15: JUZH_3B4(JieLi, 준비 중) 업데이트 창: UBOOT 진입·백업, 쓰기는 준비 중

## 10. 노브 없는 보드에서 다른 점

- 대상: SAYO_3X3(9키), SAYO_2X4(8키), SAYO_2X6(12키). SAYO_2B3(6키)는 [11장](#11-무선-키보드-sayo_2b3와-동글-준비-중)도. 보드별 값은 [BOARDS.md](BOARDS.md)
- 같은 GUI·문자열 문법 사용

```
 9키 SAYO_3X3          8키 SAYO_2X4
 ┌───────────────┐     ┌───────────────────┐
 │ [A]  [B]  [C] │     │ [A]  [B]  [C]  [D]│
 │ [D]  [E]  [F] │     │ [E]  [F]  [G]  [H]│
 │ [G]  [H]  [I] │     └───────[USB]───────┘
 └─────[USB]─────┘
```

| 항목 | 노브 있는 보드 | 노브 없는 보드 |
|---|---|---|
| 패턴 입력 시작 | 노브 2초 | **아무 키 2초**. 단계는 키만 |
| 키 입력 시점 | 패턴 암호가 있으면 노브 누르기는 뗄 때 | 키는 **누를 때** 입력(암호가 있어도, [REQ-KEY-05](REQUIREMENTS.md#key-입력)). SAYO_2B3도 같음(조합을 쓰면 그 키가 한 번씩 입력됨). 풀린 상태에서 2초 눌러 다시 잠그면 그 키가 한 번 입력됨 |
| LED | 1개 또는 키마다 | 키마다. 누르는 동안 누른 키만 초록, 나머지는 꺼짐 (꽂을 때 LED 점검은 모든 보드) |
| 저장 용량 | 128바이트 | 4096바이트 (문자열 수천 자) |
| 업데이트 모드 진입 키 | 키 D | 왼쪽 아래 키 (9키: 키 7 = G, 8키: 키 5 = E) |

### 이력

- 2026-11-07: 노브 없는 보드는 키를 누를 때 입력(전에는 뗄 때), LED 점검을 색 바퀴로
- 2026-11-07: 누르는 동안 나머지 LED 꺼짐(전에는 파랑)
- 2026-11-16: 대상에 SAYO_2X6, 요구사항 식별자 참조
- 2026-11-07 이전 9키 펌웨어는 1줄 LED가 파랑만 켜짐 → 업데이트 ([TROUBLESHOOTING 3-8](TROUBLESHOOTING.md#3-8-9키sayo_3x3-1줄-led가-파랑만-켜짐))

- USB 케이블을 꽂으면 유선으로, 뽑으면 블루투스로 자동 전환
- 패턴 암호는 유선과 같음([4장](#4-패턴-암호-잠금)). 잠긴 채 유선↔무선이 바뀌어도 잠김 유지
- GUI 연결 막대 넷째 줄에 배터리 표시(`🔋 배터리 80%`). 케이블 연결 중에는 충전 때문에 값이 높게 나와 `🔌 충전 중 · 연결 전 62% (5분 전)`처럼 케이블을 꽂기 전 값을 보여 줌(없으면 "참고값"). 낮음은 주황, 위험은 빨강
- 전원 스위치 SW1을 켜야 USB로도 잡힘(꺼져 있으면 꽂아도 장치 없음)
- 키마다 LED는 없음. 상태 LED 6개

| LED | 뜻 |
|---|---|
| 흰색 짧게 깜빡임 | 키 입력 |
| 초록 계속 | USB 유선 연결됨 |
| 빨강 5초마다 짧게 | 배터리 부족(약 3.4 V 아래) |
| 빨강 빠르게 3번 뒤 꺼짐 | 배터리 매우 부족(약 3.1 V) → 절전. 충전 뒤 SW1 다시 켜기 |
| 지금 슬롯의 파랑 빠르게 깜빡임 | 블루투스 페어링 대기 |
| 지금 슬롯의 파랑 느리게 깜빡임 | 기억한 기기에 다시 연결 중 |
| 지금 슬롯의 파랑 3초 켜짐 | 블루투스 연결됨 |
| 키 6을 누른 채 키 1을 1초 → 파랑 1~3개 | 배터리 잔량(3개 >66%, 2개 >33%, 1개 그 아래) |
| 빨강 깜빡임(1초 주기) | 업데이트 모드(자체 부트로더) |
| 빨강·초록(충전 IC) | 충전 중·충전 완료(펌웨어와 무관) |

### 블루투스 연결

| 하고 싶은 것 | 방법 |
|---|---|
| 처음 연결 | USB를 뽑고 SW1 켜기(지금 슬롯에 기억한 기기가 없으면 바로 페어링 대기, 그 슬롯 파랑 빠르게 깜빡임) → PC·폰의 블루투스 "장치 추가"에서 `SAYO_2B3` 고르기 |
| 다시 연결 | SW1 켜기 또는 USB 뽑기 → 지금 슬롯의 기기에 자동 연결 |
| 다른 기기와 새로 연결(재페어링) | 지금 슬롯만: **키 5 + 키 6을 2초**, 또는 **키 5(아래 줄 가운데)를 누른 채 SW1 켜기** → 새 주소로 페어링 대기([아래](#블루투스-슬롯-3개)) |
| 광고가 멈췄을 때 | 아무 키나 누름 → 다시 연결 시도(그 키는 입력되지 않음) |

- 연결을 기다리는 시간은 60초. 그 안에 연결되지 않으면 파랑이 꺼지고 멈춤(배터리 절약)
- PC·폰에 남은 옛 `SAYO_2B3` 항목은 제거해 두기(Windows: 설정 → Bluetooth 및 장치 → `SAYO_2B3` → 장치 제거)
  - 1단계 펌웨어(슬롯 하나)는 옛 항목을 남긴 채 재페어링하면 붙었다 끊기기를 반복했음 ([TROUBLESHOOTING 3-10](TROUBLESHOOTING.md#3-10-무선sayo_2b3-붙었다-끊기기를-반복))

### 블루투스 슬롯 3개

- 기기 3대(슬롯 1·2·3)를 기억하고 조합으로 바꿈. 지금 고른 슬롯의 기기만 연결. 고른 슬롯은 전원을 꺼도 기억
- 파랑 L8 / L7 / L6 = 슬롯 1 / 2 / 3(키 1 / 2 / 3과 같은 순서)

| 하고 싶은 것 | 방법 |
|---|---|
| 슬롯 바꾸기 | **키 6을 누른 채 키 1 / 2 / 3을 2초** → 키보드가 잠깐 다시 켜지고 그 슬롯 파랑 1초 |
| 지금 슬롯만 재페어링 | **키 5 + 키 6을 2초**, 또는 키 5를 누른 채 SW1 켜기 → 키보드가 새 주소로 다시 켜져 페어링 대기. 다른 슬롯 기기는 그대로 |
| 배터리 잔량 | 키 6을 누른 채 키 1을 1초(계속 2초 누르면 슬롯 1로 바뀜) |

- 정확히 두 키만. 다른 키도 함께 누르면 아무 일도 안 함
- 키 5·6도 다른 키처럼 **누를 때** 바로 입력됨(겹쳐 쳐도 버리지 않음, [REQ-KEY-08](REQUIREMENTS.md#key-입력)). 장입됨, 기판 확인 전
  - 그래서 조합을 쓰면 누른 두 키의 문자열이 한 번씩 입력된 뒤 동작함(예: 키 6 + 키 2 → 키 6·키 2 문자열 입력 뒤 슬롯 2). 조합을 쓸 때는 입력받을 창이 없는 곳에서
- 재페어링하면 PC·폰에는 **새 장치**로 보임 → "장치 추가"로 새로 연결하고, 남은 옛 `SAYO_2B3` 항목은 제거해 두기
- 슬롯마다 키보드 주소가 달라 PC·폰에는 슬롯마다 다른 `SAYO_2B3` 장치로 보임 → 다른 슬롯의 기기는 붙지 않음
- 기기가 페어링된 슬롯은 다른 기기의 블루투스 검색에 보이지 않음(그 슬롯 기기만 붙음). 휴대폰처럼 주소가 바뀌는 기기의 슬롯은 검색에 보일 수 있으나 새 기기는 페어링 안 됨(추정)
  - 그 슬롯에 새 기기를 붙이려면 **키 5 + 키 6을 2초**(재페어링)
  - 모든 슬롯을 한꺼번에 지우려면 GUI [공장 초기화](#공장-초기화)
- 한계: 서로 다른 슬롯에 휴대폰 2대처럼 주소가 바뀌는 기기를 두면 키보드가 구분하지 못해 다른 슬롯의 휴대폰이 붙을 수 있음([REQ-BLE-14](REQUIREMENTS.md#ble-무선동글), 결정 대기)
- ⚠️ 2026-11-16 판(131,648 B)으로 올리면 페어링 저장 위치가 바뀌어 기존 연결을 못 씀 → PC·폰에서 `SAYO_2B3` 장치를 제거하고 슬롯마다 다시 페어링
- ⚠️ 1단계 펌웨어에서 슬롯 3개 펌웨어로 올리면 키보드 주소가 바뀌어(슬롯 1 포함) 예전 연결을 못 씀 → PC·폰에서 옛 `SAYO_2B3` 장치를 제거하고 다시 페어링(슬롯 1 포함)
- 기기 한 대를 여러 슬롯에 연결하는 것은 확인 전(본딩이 엉킬 수 있음, 추정). **기기 한 대는 슬롯 하나**(결정 대기 [REQ-BLE-09](REQUIREMENTS.md#ble-무선동글))

- 파일: `macro_keyboard-SAYO_2B3.bin`. GUI 업데이트 창 또는 `tools\flash.ps1 -Board sayo_2b3` ([BOOTLOADER_CH573.md](BOOTLOADER_CH573.md#업데이트-자체-부트로더-hidboot))

### 동글 (USB 블루투스 수신기)

- 우리 동글 펌웨어는 **일반 블루투스(BLE) 키보드**를 받아 PC에 USB 키보드로 넘김. 키보드와 함께 쓰는 것은 다음 단계
- ⚠️ 아직 장입하지 않음. 동글에 처음 올리면 공장 펌웨어와 공장 짝짓기가 영구히 지워짐
- 동글에 버튼·LED가 없음 → 조작은 **빠르게 다시 꽂기**(꽂은 뒤 3초 안에 뽑기)만

| 하고 싶은 것 | 방법 |
|---|---|
| 처음 짝짓기 | 그냥 꽂기(짝지은 키보드가 없으면 바로 짝짓기 대기) → 키보드를 짝짓기 대기로 |
| 다른 키보드와 짝짓기 | **3번** 빠르게 다시 꽂기 → 60초 동안 짝짓기 대기. 못 찾으면 옛 키보드로 다시 연결 |
| 짝 정보 지우기 | **5번** 빠르게 다시 꽂기 → 지우고 짝짓기 대기 |
| 다시 연결 | 꽂기만 하면 짝지은 키보드에 자동 연결 |

- 짝짓기 대기 중에는 근처에서 신호가 가장 센 블루투스 키보드에 붙음 → 다른 블루투스 키보드는 꺼 두기
- 키보드가 암호 입력을 요구하면 동글이 `000000`을 보냄
- 동글은 키보드 1대만 기억함
- 연결이 끊기면 눌린 키를 모두 뗀 것으로 처리
