# 3X3V_RGB 보드 (9키)

- 제품: SayoDevice 계열 9키 매크로 키패드 (같은 계열 8키 = Keyb T8B7, [2X4V_RGB](PORT_CH32V203.md))
- 칩: **CH32V203C8U6** (RISC-V QingKe V4, 플래시 64 KB, RAM 20 KB, USB 풀스피드)
- 구성: 3×3 키, **노브 없음**, 키마다 3색 한 칩 RGB LED
- 확인 근거: [test_ch32v203](../tests/hw/ch32v203/test_ch32v203/README.md) 시험(2026-11-05), 분해 확인(사용자)

## 키 배치

(그림: 사용자가 추가)

| 키 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| 핀 | PB15 | PA14 | PA4 | PB10 | PA15 | PA3 | PB2 | PB11 | PB1 |

- 번호: 왼쪽 위부터 행 순서 (1~3 윗줄)
- 누르면 낮음, 내부 풀업
- PA14·PA15는 SWD/JTAG 핀 → SWJ를 끄고 사용 (디버거 연결 불가)
- PB2(키 7)는 BOOT1과 같은 핀

## LED

(그림: 사용자가 추가)

| 줄 | 키 | 빨강 | 초록 | 파랑 |
|---|---|---|---|---|
| 1 | 1·2·3 | PA11 | PA12 | PA13 |
| 2 | 4·5·6 | PA8 | PA9 | PA10 |
| 3 | 7·8·9 | PA0 | PA1 | PA2 |

- WS2812가 아님. 줄마다 색별 핀 1개를 키 3개가 공유, **낮추면 켜짐**
- 초록이 훨씬 밝음 → 펌웨어에서 색별 밝기 보정
- PA11/PA12는 USBD(장치 전용 USB)의 핀이지만 이 보드는 USBD를 안 씀 → 일반 핀으로 1줄 빨강·초록 사용 (실물 확인 2026-11-07: 1줄 빨강·초록·흰색, USB 정상)
  - 칩 자료표 48핀 표: PA11/PA12 = USBDM/USBDP(USBD), PB6/PB7 = USBFS_DM/DP. 본 펌웨어·시험 펌웨어는 USBFS로 동작 → USB 커넥터는 PB6/PB7
  - PB6이 시작부터 낮게 읽힌 이유: USB D−(호스트 풀다운)
  - PB6/PB7은 풀업하지 않음 (`hal_init`)
- 키별 제어 가능 여부: 미확인 (애노드 배선을 모름, 아래 "참고 키보드로 확인할 것")
- ⚠️ **남는 핀을 풀업**해야 LED가 켜짐. 떠 있으면 LED 핀을 낮춰도 안 켜짐 (2026-11-07 확인). 남는 핀 중 하나가 LED 전원을 켜는 듯(어느 핀인지 모름)
- 2·3줄의 R·G·B를 한꺼번에 낮추면 빨강만 보임 (2026-11-07, 저장 흰색도 빨강). 빨강의 전압이 낮아 공통 저항을 같이 쓰면 초록·파랑이 꺼지는 것으로 추정
  - 펌웨어: 섞은 색은 한 번에 한 색씩 번갈아 켬(색마다 1/3 시간). 실물 확인: 저장 때 2·3줄 흰색 (2026-11-07)

## 부팅·장입

- 부트로더 진입: **BOOT 브리지**(BOOT1 실크 아래 패드 2개)를 이은 채 USB 연결
- 소프트웨어 진입 불가 (부트로더로 점프하면 `csrw 0xbc0`에서 예외)
- 장입: `wchisp flash <bin>` → 브리지 제거 → USB 재연결
- ⚠️ 제조사 펌웨어는 읽기 보호. 보호 해제 때 지워짐(되돌릴 수 없음)

## 확인된 것 / 모르는 것

| 항목 | 상태 |
|---|---|
| 칩, USB 인식(시험 펌웨어) | 확인 |
| 키 9개 핀 | 확인 |
| LED 핀·극성 | 확인 |
| 노브 | 없음(확인) |
| USB 핀 | PB6/PB7 (USBFS). 자료표 + PA11/PA12 LED와 USB 동시 동작으로 확인 |
| PB6 | 시작부터 낮게 읽힘 = USB D− |
| LED 전원 | 남는 핀 풀업이 필요(어느 핀인지 모름) |
| LED 키별 제어 | 모름 |
| 1줄 빨강·초록(PA11/PA12) | USB와 무관, 사용 (확인) |
| 칩 ID(HELLO 값) | `0x19`로 임시 지정 |

## 본 펌웨어에서의 동작

- 빌드·상태: [PORT_CH32V203.md](PORT_CH32V203.md)
- 잠금(패턴 암호)·자동 잠금 있음: 노브 대신 **아무 키 2초**로 패턴 입력 시작, 단계는 키만
  - 암호가 있으면 키는 뗄 때 입력
- LED: 줄 단위로 같은 색 (상태 표시)
- GUI 업데이트 창으로는 장입 불가 → wchisp 사용

## 참고 키보드로 확인할 것 (원본 펌웨어 그대로)

> 원본 펌웨어를 지우지 않음. 보호 해제(unprotect) 금지

1. SayoDevice 웹 도구에서 키마다 다른 색 지정
   - 같은 줄 3키가 서로 다른 색 → 키별 제어 회로 있음 → LED 주변 핀 측정
   - 항상 같은 색 → 줄 단위가 하드웨어 한계
2. USB 디스크립터: VID/PID, 인터페이스 수, 리포트 형식
3. 웹 도구의 WebHID 통신 관찰 (설정 방식 참고)
4. BOOT 브리지 + `wchisp probe`로 읽기 보호 상태만 확인 → 보호가 없으면 플래시 덤프·분석
