# KEY12-JUZHEN_V01 (12키 + 노브 2)

- 요약 표: [BOARDS.md](../BOARDS.md#준비-중-보드). 같은 무선 보드: [SAYO_2B3](BOARD_SAYO_2X3B_RGB.md). 새 보드 절차: [NEW_BOARD.md](../NEW_BOARD.md#9-식별-전-보드)
- **상태: 식별 중(공장 펌웨어 보존)**. 칩은 JieLi **AC6956C**로 판단(핀 대조 + 31번 도통, 사용자 확인). 이식 가능성은 판단 보류(SDK·장입 경로 조사됨, 미검증. [JieLi SDK·장입](#jieli-sdk장입-조사))

## 1. 개요

- 보드 ID: **JUZH_3B4** (8자, 3행 × 4열 + B = 블루투스, SAYO_2B3과 같은 방식). 노브 2개는 이름에 없음
- 기판 표기: `KEY12-JUZHEN_V01` (문서 파일 이름도 이 표기 그대로)
- 제품: 판매처 확인 필요(Sayo 기판 표기 형식과 달라 Sayo 제품이 아닐 가능성이 큼, 추정)
- 구성(사용자 관찰, 2026-11-15)
  - **12키 + 노브 2**, 3행 × 4열
  - 키마다 LED(종류 확인 필요)
  - 배터리, 전원 On/Off 스위치, 블루투스
  - 버튼 1개: 누를 때마다 노브 사이 RGB LED 3개가 번갈아 켜짐(연결 슬롯 표시로 추정)
  - 노브 사이 충전 LED 2개: 빨강 = 충전 중, 초록 = 완충(충전 IC 또는 칩 충전부가 켜는 것으로 추정, 확인 필요)
  - J4: 사각·원형 패드 2개(부트 핀 추정, 확인 필요)
- 칩: **JieLi(杰理) AC6956C**(핀 대조 + 31번 도통 확인). 판단 근거는 [칩 식별](#칩-식별-jieli-32핀)
  - 각인 `BP3D136-21A4`는 다른 표기(웹 검색 일치 자료 없음). 각인 위 π 모양 마크 = JieLi 로고(사용자 확인)
  - QFN32 4 × 4 mm. 칩 왼쪽 위 흰 실크 점은 AC6956C **8번과 9번 사이 모서리**(사용자 확인). 칩 표면 딤플·모서리 표시 없음
  - 크리스털 `24.000` = 24 MHz
  - 칩 특성(AC6956C 데이터시트): BT 5.1 BR/EDR + BLE, USB 2.0 FS OTG, 배터리 충전 입력. 원래 블루투스 스피커용 SoC
- USB(공장 펌웨어, PM이 읽기만 함, 2026-11-15)
  - **HID 키보드로 잡힘**. 처음 한 번은 안 잡혔음(원인 미확인: 케이블·전원 스위치 추정)
  - VID:PID **`514C:8850`**, bcdDevice `0x0100`, 시리얼 `CD71134331353930`, 제조사·제품 문자열 없음. VID `0x514C`는 웹 검색으로 소유자 못 찾음
  - 인터페이스 0: 벤더 HID(Usage Page `0xFF00`), Report ID 3, 입력·출력 64바이트. 공장 설정 채널([아래](#공장-설정-프로그램프로토콜-884x-계열-추정))
  - 인터페이스 1: 키보드(ID 1, 6키), 마우스(ID 2), 키보드(ID 4, 9키 + LED 5개), Consumer(ID 5, 16비트)
- 개발 보드 UID: 해당 없음

### 칩 식별 (JieLi 32핀)

- 결론: **JieLi AC6956C**(핀 대조 + 31번 도통 확인, 사용자 측정, 2026-11-15). 핀 기능이 같은 JL7016C8은 31번(DAVSS = 접지)이 접지가 아니라 제외
- 자료: JieLi AC6956C Datasheet Version 1.1(2020-03-19), Figure 1-1·Table 1-1, QFN32 4 mm × 4 mm, SZLCSC 배포본

| 크리스털 | 24 MHz | 24 MHz |
| 패키지 | QFN32, 4 × 4 mm | QFN32 4 × 4 mm |
| 무선·USB | BLE, USB HID 동작 | BT 5.1 BR/EDR + BLE, USB 2.0 FS |

| VBAT | 10번(도통 확인) | 10 VBAT |

| BT_AVDD | 11번(도통 확인) | 11 BT_AVDD |

- 1번 핀: 실크 점은 AC6956C **8번과 9번 사이 모서리**(사용자 확인, 2026-11-15). 칩 표면 표시가 없어 판단 근거는 **핀 기능**(USB·VBAT·11번·RF·OSC)
  - 실크 점 모서리의 9번을 1번으로 하는 칩이라면 AC6956C 번호에서 8을 뺀 번호: RF 8, OSC 9·10, VBAT 2, BT_AVDD 3, USB 15·16
  - PM이 대조한 JieLi 32핀 10종 중 이 기준으로 맞는 칩은 없음(AC6321A는 RF·OSC만 맞음, 아래 표)
  - 판단(추정): 기판 풋프린트의 실크 점이 칩 1번 핀과 다른 모서리에 있음
- 사용자 계수(크리스털 23·24, 안테나 25): 실크 점에서 시계 방향 첫 핀(= 8번)을 1로 셈 → 실제 번호 = 9 − 계수(32로 나눈 나머지). 23 → 18(BT_OSCO), 24 → 17(BT_OSCI), 25 → 16(BT_RF)로 맞음. 문서는 데이터시트 표준 번호로 씀

### JieLi SDK·장입 (조사)

- PM 조사(2026-11-15, 웹 자료만, 장치에는 아무것도 안 함). 모두 미검증
- 칩 계열: AC6956C = AC695N 계열, 내부 코드 **BR23**(AC635N과 같은 계열). CPU pi32v2. 출처 `github.com/kagaimiq/jielie` `chips/br23`
- SDK: 공식 `github.com/Jieli-Tech/fw-AC63_BT_SDK`(Apache-2.0)
  - 지원: AC631N·AC635N·AC636N·AC637N·AC632N. "AC69 계열은 오디오 없이 호환"이라 적혀 있음
  - `apps/hid`에 키보드·마우스·리모컨 예제
  - AC635N이 BR23이라 AC6956C에 쓸 수 있을 것으로 추정(미검증)
  - 빌드: JieLi 전용 컴파일러(Windows, Code::Blocks 또는 `make_prompt.bat`). 내려받기는 사용자 허락 뒤
  - 오디오용 AC695N Soundbox SDK는 별도(비공식 배포처)
- 장입: 칩 ROM의 USB 다운로드 모드(**UBOOT**)
  - 들어가는 법: USB 선에 "USB_KEY" 신호(`0x16EF`, D+ 클럭·D− 데이터, 약 50 kHz, 4.7 kΩ 이하 풀업)를 보냄. 보통 JieLi "USB 업데이터(강제 업그레이드 도구)" 동글을 씀
  - 플래시가 비었거나 부팅에 실패하면 자동 진입. 핀 스트래핑 방식은 아님
  - 출처: `kagaimiq/jl-uboot-tool` 저장소의 how-to-enter-uboot.md, `jielie` `isp/usb/usb-key.md`
- 공장 펌웨어 백업: 공개 도구 `kagaimiq/jl-uboot-tool`이 BR23(AC695N/AC635N)을 "Working"으로 표시. `read` 명령으로 플래시 전체 읽기 가능
  - 플래시 용량은 직접 확인해야 함(플래시 ID 또는 칩 표기)
  - → UBOOT 진입만 되면 백업 가능성 있음(미검증). **쓰기 전 반드시 전체 백업**
- 위험·미확인
  - 칩 키·암호화를 요구하는지 자료에 없음(미확인)
  - `erasechip`은 "안 될 수 있음"으로 적혀 있음
  - 공식 장입 도구 이름(`isd_download` 등) 미확인
- 다음(사용자 결정 필요)
  - UBOOT 진입 수단: USB 업데이터 동글 구입, 또는 USB_KEY 송신기 자작(CH32V203 보드 활용 가능, 추정)
  - JieLi 컴파일러 내려받기: 사용자 허락 뒤

### 공장 설정 프로그램·프로토콜 (884x 계열 추정)

- 제조사 설정 프로그램: `szxiaozi.com/tool.zip`(사용자가 받음, 저장소 밖에 보관)
  - 안의 파일: Windows `MINI_KEYBOARD.exe`(Qt5, hidapi), Mac `MINI_KEYBOARD.pkg`
  - 실행하지 않고 문자열만 봄(PM, 2026-11-15): `hid_write`/`hid_read` 사용. 레이어·LED 모드·RGB LED·멀티미디어·마우스 키 설정 화면. 칩 이름 문자열 없음
- 공개 도구 `ch57x-keyboard-tool`(`github.com/kriomant/ch57x-keyboard-tool`, 소스 1.6.2)과 대조
  - 같은 계열 저가 매크로 키보드용. README 지원 목록에 "3×4 with 2 knobs (Bluetooth version)"이 있음
  - 기본 VID `1189`(Trisat), PID `8840`·`8842`·`8890`. 소스는 PID `0x8850`도 884x 방식으로 처리(자동 검색 목록에는 없음, `--product-id`로 지정)
  - 설정 패킷: 64바이트, 첫 바이트 `0x03`(예: `03 FE` 키 레이어+1 …) → 이 보드 벤더 HID의 Report ID 3·64바이트와 맞음
- 결론(추정): 공장 펌웨어는 이 "884x" 설정 프로토콜 계열. VID만 `514C`로 다름. 도구 이름의 ch57x는 계열 이름일 뿐 칩과 무관(칩은 JieLi)
- 뜻: **공장 펌웨어를 그대로 두고 키 설정만 바꾸는 길**이 있을 수 있음(장입 불필요)
  - 단 벤더 채널에 쓰면 공장 설정 영역이 바뀜 → **사용자 승인 뒤에만**. 지금까지 설정을 바꾸는 명령은 보내지 않음

#### 공장 채널 읽기 시험 (2026-11-15)

- 사용자 지시로 PM이 시험. 설정을 바꾸는 명령은 보내지 않음
- 수동 대기 3초: 장치가 먼저 보내는 보고서 없음
- Report ID 3 + 0으로 채운 64바이트(공개 도구의 초기화 패킷과 같은 내용): 응답 없음
- 조회 명령 `03 FB FB FB` + 0(65바이트 쓰기, 64바이트 읽기): 공장 프로그램을 역어셈블해서 찾음(실행 안 함). 공장 프로그램이 연결할 때 보냄
- 응답: `03 FB 0C 02 0B` + 0
  - 공장 프로그램은 응답 [2]·[3]·[4] 세 바이트를 전역 변수 3개에 저장. 문자열 `Cur_KeyBoard_KeyNum[2]`가 있음
  - 해석(추정): 키 12개(`0x0C`), 노브 2개(`0x02`), 기종·버전 `0x0B`
- 쓰기 명령(예: `03 FE …`)은 미시험. 사용자 승인 뒤

#### 쓰기 명령 (조사 중, 2026-11-15)

- 장치에는 아무것도 보내지 않음. 문서·역어셈블 분석만
- 공개 도구 884x 형식(출처: `ch57x-keyboard-tool` 1.6.2 `k884x.rs`)
  - 키 지정: `03 FE 키ID 레이어+1 종류 00 00 00 00 00` + 데이터. 종류: 1 키보드, 2 미디어, 3 마우스
    - 키보드: [10] = 개수, 이어서 (수정키, 키코드) 쌍. 최대 18쌍
    - 미디어: [10] = 0, [11..12] = Consumer 코드(리틀 엔디언)
  - 매 지정 뒤 `03 AA AA`, `03 FD FE FF`, `03 AA AA`
  - 키ID: 키 1~12 = `0x01`~`0x0C`. 노브 0 = `0x10`/`0x11`/`0x12`(반시계/누름/시계), 노브 1 = `0x13`/`0x14`/`0x15`. 레이어 0~2
  - LED: `03 FE B0 레이어+1 08 00 05 01 00 코드 00 34`, 끝 `03 FD FE FF 00 3D`
- 공장 프로그램 역어셈블(실행 안 함)에서 찾은 명령

| 명령 | 쓰임 | 상태 |
|---|---|---|
| `03 FB FB FB` | 조회(키 수·노브 수·기종) | 시험 완료 |
| `03 FA …` | 쓰기 뒤 64 B를 읽는 반복문에서 씀. LED 패킷도 `03 FA B0 레이어`로 만듦 | 미시험. 기종 바이트(조회 응답 [4])를 9와 비교하는 분기 있음 |
| `03 FE …` | 키 패킷 표에 있음 | 어느 기종용인지 미확인 |
| `03 EF EF` | 인자 없음 | 뜻 미확인 |
| `03 FC FC xx xx` | 값 0~16을 고르는 인자 | 뜻 미확인 |

- 결론(조사 중): 쓰기 형식은 884x(`FE`)로 추정. 단 이 기종(`0x0B`)은 `FA` 변형일 가능성(추정) → 미확정
- 쓰기 시험은 더 분석한 뒤 사용자 승인을 받고 함

### 공장 펌웨어 보존 (지킬 것)

- **장입·지우기·읽기 보호 해제·장입 도구의 "다운로드"는 하지 않음.** SAYO_2B3은 시험 펌웨어 장입으로 공장 펌웨어·짝짓기가 영구히 지워졌음
- **J4를 GND 등에 잇지 않음.** 연결처만 잼(부트 모드에서 도구가 자동으로 지울 수 있음)
- **벤더 HID 채널에 설정을 바꾸는 보고서를 보내지 않음**(공장 설정·부트 명령일 수 있음). 읽기 조회(`03 FB`)만 사용자 지시로 시험함. 설정 프로그램·`ch57x-keyboard-tool`로 쓰는 것도 사용자 승인 뒤
- 공장 펌웨어 백업: UBOOT 진입 뒤 `jl-uboot-tool` `read`로 가능할 수 있음(미검증). **백업 전에는 쓰기·지우기 금지**, 첫 장입은 사용자 별도 승인
- 공장 동작(키 기본 입력, 노브, 블루투스 이름, 설정 프로그램 화면)을 먼저 기록

- 키 LED: 종류(단색/RGB/WS2812류)·구동 방식 확인 필요

## 5. 부팅·장입

- 장입 경로(조사, 미검증): 칩 ROM의 USB 다운로드 모드(UBOOT). USB 선에 USB_KEY 신호(`0x16EF`)를 보내 진입, 플래시가 비었거나 부팅 실패면 자동 진입. 핀 스트래핑 아님([JieLi SDK·장입](#jieli-sdk장입-조사))
- 진입 수단(USB 업데이터 동글 또는 자작 송신기)은 사용자 결정 필요. 칩 키·암호화 요구 여부는 미확인
- 벤더 HID 채널(인터페이스 0)은 공장 설정용, 884x 계열 프로토콜로 추정. 읽기 조회만 시험, 쓰기 안 함
- 장입 없이 공장 펌웨어의 키 설정만 바꾸는 길이 있을 수 있음([1절](#공장-설정-프로그램프로토콜-884x-계열-추정)). 사용자 승인 뒤에만
- J4 용도 확인 필요(UBOOT 진입이 핀 스트래핑이 아니라는 자료가 있어 부트 핀 추정은 약해짐, 추정). 연결 금지, 연결처만 잼
- 장입은 사용자 승인 전에는 하지 않음([1절 공장 펌웨어 보존](#공장-펌웨어-보존-지킬-것))
