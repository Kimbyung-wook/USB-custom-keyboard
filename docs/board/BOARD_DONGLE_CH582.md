# SAYO_2B3 동글 (CH582F, 키 없음)

- 요약 표: [BOARDS.md](../BOARDS.md). 짝 키보드: [BOARD_SAYO_2X3B_RGB.md](BOARD_SAYO_2X3B_RGB.md)

## 1. 개요

- 제품: SayoDevice 6키 블루투스 키보드(SAYO_2B3)와 함께 오는 USB 동글
- 칩: CH582F (QFN28). 칩 특성은 [CHIPS.md](../CHIPS.md)
- 구성: USB 플러그, 칩, 안테나. **버튼·LED 없음**(사용자 확인, 2026-11-13)
- 보드 ID: 없음(GUI 보드 목록 대상 아님, 설정 통신 없음). USB 제품 이름 `BT Dongle`
- 개발 보드 UID: 확인 필요(`wchisp info` 전)
- 공장 펌웨어: USB `8089:0008`로 잡힘(사용자 관찰, 2026-11-13). 키보드 공장 펌웨어는 이미 지워져 공장 짝짓기는 쓸 수 없음. USB 문자열·HID 컬렉션: 부록
- 우리 펌웨어: `firmware/dongle_ch582` ([README](../../firmware/dongle_ch582/README.md)). 핀 시험: `tests/hw/ch582_dongle` ([README](../../tests/hw/ch582_dongle/README.md)): 쓰는 USB 포트, 32 kHz 크리스털 유무, 풀업·풀다운 상태, 핀별 H/L 구동(LED 찾기), 버튼 핀을 USB 키보드로 입력
- 확인 근거: 칩 표기·버튼/LED 없음은 사용자 관찰. 핀 번호는 자료표 CH583DS1. 나머지는 코드 기준, 하드웨어 확인 전

## 2. 버튼 배치와 매핑

- 해당 없음(키·버튼 없음). 조작은 USB 재꽂기만(6절)

## 3. 칩 핀맵

- 그림 없음(핀 확인 전)
- QFN28 배치는 CH573F와 같음 → 번호는 [SAYO_2B3 3절](BOARD_SAYO_2X3B_RGB.md#3-칩-핀맵) 표와 같음

| 핀 번호 | 이름 | 용도 | 비고 |
|---|---|---|---|
| 17 | PB22 | ROM 부트로더 다운로드 설정 핀(추정) | GND에 댄 채 꽂기. 동글 기판에 패드 없음 → 칩 핀에 직접 |
| 12 | PB11 | USB1 UD+ | 다운로드 설정 핀 후보(PB22로 안 되면) |
| 확인 필요 | PB10 | USB1 UD− | |
| 확인 필요 | PB12 / PB13 | USB2 UD− / UD+ | 동글이 USB1·USB2 중 어느 쪽을 쓰는지 확인 필요(핀 시험 `USB<n>`) |
| 확인 필요 | PA10 / PA11 | 32 kHz 크리스털(X32KI / X32KO) | 크리스털 유무 확인 필요(핀 시험 `X32K`). 펌웨어는 켤 때 재서 판단 |
| 확인 필요 | 그 밖 | 전원·GND·안테나·안 쓰는 핀 | |

## 4. LED

- 해당 없음(LED 없음). 펌웨어는 LED 핀을 −1(없음)로 빌드(`firmware/dongle_ch582/src/board.h`)

## 5. 부팅·장입

- ROM 부트로더 진입(추정, 키보드 CH573F와 같은 방식): **PB22(17번)를 GND에 댄 채 USB에 꽂기** → `4348:55E0`
  - 통신이 없으면 몇 초(키보드에서 약 6~15초 관찰) 뒤 앱으로 돌아감 → 바로 장입
  - 드라이버: WinUSB(Zadig). CH375 드라이버면 wchisp가 못 엶
- 확인(읽기만): `wchisp info` → 칩 CH582, `CFG_ROM_READ`(읽기 보호), UID
- 장입: `firmware/dongle_ch582` 또는 `tests/hw/ch582_dongle`에서 `mingw32-make flash`(wchisp)
- 순서: 핀 시험 → 본 펌웨어
- ⚠️ **첫 장입은 공장 펌웨어와 짝짓기를 영구히 지움** → 사용자 별도 승인 뒤에만
- 자체 부트로더 없음, 앱에서 들어가는 BOOT 명령 없음 → 다시 장입할 때마다 ROM 부트로더(PB22) 필요. BOOT 명령은 나중에 정함

## 6. 본 펌웨어에서의 동작

- 역할: 일반 BLE HID 키보드(HOGP)에 중앙기기(central)로 붙어 받은 보고서를 USB HID로 넘김. 키보드 쪽은 동글 전용 처리가 없음
- USB `1209:C55F`(확정), 제품 이름 `BT Dongle`. 부트 키보드 + 소비자·시스템 키·마우스
- 빌드: `firmware/dongle_ch582`에서 `mingw32-make` → `build/dongle.bin`. SDK `MK_CH58X_SDK`(CH583 EVT). 크기: 플래시 169,424 B, 정적 RAM 약 13 KB
- PC 시험: core 논리 93개, `uv run pytest`에 포함(`tests/gui/test_dongle_host.py`)
- 클록: 60 MHz PLL. 32 kHz 크리스털이 있으면(100 ms에 2,900~3,700 클록) 크리스털, 없으면 내부 LSI + 120초마다 보정
- 저장: Data-Flash 연결 장치 기록 0x7000(탐색 캐시), 재꽂기 횟수 0x7800, BLE 짝 정보 0x7E00~

| 상태 | 들어가는 조건 |
|---|---|
| 짝짓기 | 짝 정보 없음(시간 제한 없음), 3번 빠르게 재꽂기(60초) |
| 재연결 | 짝 정보 있음. 짝지은 주소로 바로 연결 요청, 시간 제한 없음 |
| 준비 | 암호화·알림 구독 끝 → 키 입력 전달 |

- 빠르게 재꽂기 = 꽂은 뒤 3초 안에 뽑기. 5번이면 짝 정보 지우고 짝짓기
- 짝짓기: HID 광고 + 검색 가능 + 연결 가능 장치 중 신호가 가장 센 것. 실패한 장치는 이번 짝짓기에서 뺌. 새 장치가 준비되면 옛 짝 정보를 지움(1대만)
- 암호키를 요구하면 `000000`
- 끊기면 눌린 키를 모두 뗌. Report Map을 못 쓰면 부트 프로토콜로 대체
- 제한: 주소가 바뀌는(RPA) 키보드 재연결 안 될 수 있음, HID 서비스 1개·보고서 8개·Report Map 512 B, USB 원격 깨우기 없음, 상태 표시 없음

## 부록: 공장 펌웨어 식별 기록

> 2026-11-13, 공장 펌웨어 그대로인 동글을 PC에 꽂아 관찰(hidapi, `tools/usb_monitor.ps1`). 키보드 쪽 기록: [SAYO_2B3 부록](BOARD_SAYO_2X3B_RGB.md#부록-공장-펌웨어-시절-식별-기록)

- USB: `8089:0008` 복합 장치, 제조사 "SayoDevice", 제품 "SayoDevice 2x3B", bcdDevice 0x089A, 일련번호 `03705437626441DA420000000000`
- 키보드 유선 모드와 **같은 VID/PID**, **일련번호는 다름**(키보드 `0361383061150C36400000000000`)
- 꽂고 약 13초 뒤 일부 인터페이스가 빠졌다 다시 잡힘(재연결로 보임, 원인 미확인)
- 인터페이스 2개, HID 컬렉션(usage page / usage)
  - MI_00: 키보드(0x01/0x06)
  - MI_01: 제조사 전용 0xFF00/0x01, 제조사 전용 0xFF11/0x02, 키보드, 마우스(0x01/0x02), 소비자 키(0x0C/0x01)
- 공장 짝 키보드를 꽂으면 바로 입력됨(짝지어진 상태로 보임). 페어링 방법·다른 키보드와 짝짓기는 확인 못 함
